## §4 — The applier (§2 event architecture, realized)

One goroutine owns the `*sql.DB` (single connection). Typed events (one Go type per §F transition class) arrive on
one queue: channel frames (per-channel FIFO readers), timers (`HANDSHAKE_DEADLINE`, `ATTACH_DEADLINE`,

visible everywhere: `attempt_open_ok`, `turn_receipt`, `ticket_granted`, receipts, `turn_open`); reads for the
terminal surface + disclosure assembly are committed-snapshot queries through the loop. No ad-hoc write site exists
(grep-provable: no other package imports database/sql).

## §5 — Frames + channels (§A realized)

- Framing: `uint32_be(length) || payload`, `FRAME_MAX = 4,194,304`; oversized ⇒ channel fault ⇒ supervision.
- JCS: own small encoder over Go maps/structs (sorted keys, `,`/`:` separators, no floats on trust paths, counters
  as strings) — stdlib-only, matching the limits doc's §9 builder semantics; digests always over canonical bytes.
- Families: unknown `type` ⇒ reject-and-record `FAULT_UNKNOWN_MESSAGE`; unknown fields ignore (additive) EXCEPT the
  CLOSED broker event/ack family ⇒ reject; reply-class without `re` ⇒ malformed.
- Backpressure: bounded send queues, writers block ≤ `SEND_DEADLINE`, full-past-deadline CTRL ⇒ channel fault;
  wake/advisory class droppable.
- Channels: CTRL-W/CTRL-C/DATA-P as `socketpair(AF_UNIX, SOCK_STREAM)` created immediately pre-spawn; child inherits
  exactly its own endpoints; close-on-exec on parent side; m-10 never holds a DATA-P endpoint post-spawn; runtime
  sockets/files in the 0700 private dir. Broker channel: dial-in client to `broker-control.sock` (0600) — hold
  `broker-control.lock` fcntl lock BEFORE the durable `control_generation` advance, then connect presenting
  `{control_token, control_generation}`; token handed to a SPAWNED broker via ONE inherited pipe FD.
- Sanitized spawn env: allow-list only; no secrets/handles in argv/env/FDs beyond the child's own endpoints.

- THE retirement/disposition transaction (one commit; keyed `(run_id, retiring generation_id)` committed-once;
  NO transition-ledger row — M10-C0 drop) is **TOTAL over the post-parking outcome (F2)**. Common prefix, every
  branch: retire → lease release → **E+1 mint** (fencing is never traded for a bound) → state-sensitive F59 park
  (`ISSUED`→`VOID/expired`; `CONSUMED`-no-outcome→`UNKNOWN_TOOL_OUTCOME` both rows; terminals stay;
  attempts→`UNKNOWN_PROVIDER_OUTCOME`; turn→`INTERRUPTED`) — **the parking batch always commits IN FULL, never
  truncated to remaining capacity, no prefix path exists** — → `state_seq`++. Then exactly one branch:
  **(a) ordinary (post-commit parked count ≤ `MAX_PARKED_ROWS_PER_RUN` = 512):** + G+1 prealloc (`ALLOCATED`) —
  the §B.4 step-1 successor path, unchanged; the replacement machinery proceeds (backoff → spawn).
  **(b) cap overshoot (post-commit count > 512; producer-delta §4, ratified Correction 2):** the SAME transaction
  also commits `runs.state = FAILED` + `stop_reason = parked_unknown_capacity_exceeded` and commits **NO successor
  generation row, NO lease, NO snapshot, NO same-run continuation; no revival path exists** — any next work is an
  ordinary NEW run; every parked identity stays durable and queryable past 512 (the cap is an ENFORCEMENT
  threshold at the parking write, never a storage cap); the §10 surface renders the terminal + the complete
  queryable parked set. **No-successor proof at this locus:** G+1 allocation is inside branch (a) only — on (b) no
  code path allocates, leases, or snapshots; FX-M10-CAP (i)–(iv) bind HERE (i: 511+1 ⇒ 512, branch (a), run
  continues; ii: 512+1 ⇒ 513, branch (b), full predicate in ONE transaction; iii: multi-row overshoot from 510 —
  all N durable, count legitimately exceeds 512, no truncation, branch (b); iv: no-truncation negatives).
  **(c) the G-2 10th-consecutive-failure terminal (control-plane §4):** the disposition commit writes `runs.state

  run-terminal has no replacement path; restart is an explicit operator `run start` = a new run). Branches (b)/(c)

- G-2 crash-loop: ONE durable per-run consecutive-failure counter over BOTH children, exponential backoff 2^(N−2)s

## §7 — Broker client protocol (M10-C0, realized)

`state_proposal{proposal_correlation, run_id, generation_id, turn_epoch, lease_state, state_seq}` on CI-1; at most
one outstanding proposal per run; `PROPOSAL_RESULT_DEADLINE` = `EPOCH_DRAIN_DEADLINE` + one round-trip margin
(compiled). The TOTAL receiver fold over `state_proposal_result.disposition`: `installed`-match ⇒ proof recorded;
`installed`-mismatch ⇒ fail-closed loud, no retry; `transition-started` ⇒ gate closed, await event-or-deadline then
re-propose (bounded); `rejected-transition-active` ⇒ gate closed, deadline re-propose; `rejected-stale` ⇒ INVARIANT
FAULT, no re-proposal, operator disposition; `rejected-malformed` ⇒ INVARIANT FAULT, no auto-retry; absent ⇒
deadline re-propose; dead/unknown correlation ⇒ discard; duplicate equivalent ⇒ idempotent; crash ⇒ recovery
re-proposes fresh. The TWO-FORM assign gate keyed by `{run_id, generation_id, turn_epoch, state_seq}` — a
tuple-matching `epoch_installed` event OR `installed` result opens it exactly once; stale evidence can never match
(the key includes `state_seq`). Broker event recording: the AMENDED closed family (incl `boundary_cut`;
