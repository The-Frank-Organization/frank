## 1. Frame, scope, and what is already locked

**The one job.** Make "done" **conductor-observed, not lane-asserted.** A relay is deliverable only after the trusted courier (the conductor), reading the lane's ground-truth from *outside* the lane, has run the phase-shaped done-predicate and stamped the result onto the outgoing record. Self-reported completion is **labeled, never trusted** — for a **non-authority** record it is delivered, stamped `self_reported`; for the **authority/merge (A-gate) class** a not-fully-verified record (`record_integrity ∈ {self_reported, mixed}`) is **held/escalated, not delivered** (operator decision ②, §3.2(d)/§8).

**Locked c1 contract this design builds on (NOT reopened):**
- **R3 / I3-DI-5 observe-integrity** (ARCHITECTURE.md:31-34, 70-71): every observed record carries `evidence_integrity {observed | self_reported}` (per-field, two-value); the m-3 hook is **observer-only** — a positive write-allowlist that writes only the closed m-3 observed/computed field set + a veto. The conductor reads lane ground-truth from outside the lane (DI-5).
- **m-2 schema** declares the observe/evidence FieldSpecs; m-3 fills them via the observer hook. A candidate is held in-courier through the pre-append form/lineage/observe pre-flights, then reaches **exactly one terminal outcome `{accepted | rejected | held}`** (readiness-fix-c1 seam; **no persisted `submitted` limbo** — m-7 §6/NF-S16, m-2 §17.6:269-272); `required_when` is a bounded boolean over a closed atom set; `slot_in` is the reserved opaque archetype-tag atom (m-5 owns the tag-space). Canonical-iff-consumed.
- **m-1** governed sole-writer append-only store (sole writer *within the governance surface*; the same-uid direct-store-write case is m-1's documented D5 accepted-risk — mirrored here, not re-claimed); `submit()` is one atomic conductor-owned commit; observed evidence = a point-in-time conductor snapshot on an immutable record.
- **R2** model is never a gate input (no `model_*` predicate enters the schema gate); a routing decision is a separate seat-stamped evidenced record.

**Non-goals this cycle:** no PLAN/IMPL/merge; no reopening of m-1/m-2/R2/R3; the concrete archetype tag-space stays m-5's (we reserve the seam, §5); the standalone runtime is a carry-forward, not the initial release (§8).

**Evidence base.** The audit (`c2-audit-m-3/AUDIT-planner-20260629-185522.md`) established the self-reported-done gap is universal: the upstream protocol names it but its linter is truth-agnostic (`tools/relay-lint.py:2-8`; `protocol.md:227`; `README.md:35`); jcode gates pre-action but never verifies outcome (`crates/jcode-app-core/src/tool/mod.rs:615-647`); claude-code's PostToolUse runs in-lane (`src/services/tools/toolHooks.ts:146-150`); agent-scripts is trusted-cooperative. External lit (Reward Hacking Benchmark, arXiv 2605.02964/2603.11337) shows agents tamper tests / hardcode expected artifacts and that in-reach verifiers are gameable — the empirical reason the observer must sit **outside** the lane.

## 2. The core primitive — observe-as-send

**`send` is the trigger; the conductor is the executor; the passing observation binds atomically to the relay it gates.** The agent presses "send"; the conductor runs the phase-shaped done-predicate by probing lane ground-truth from outside (DI-5); on pass, the relay is emitted stamped with *that* observation, in one atomic `submit()` commit; on an **observably-failed** predicate it bounces with the exact failing field — the candidate relay is **neither appended-as-accepted nor delivered** to any recipient; a terminal **`rejected`** evidenced outcome record naming the failing field IS committed for audit, and the lane self-corrects and re-submits a fresh candidate. *(CQ-4 settle, `c4-cq-gateconfig`: the Step-2 observe-bounce **shares** the `rejected` token — the check ran and said no — unifying with m-7 §6 / NF-S16 exactly-one-outcome; the distinct **`held`** token is reserved for the check being **unable to run** in an authority class, §3.2(d)/§8. The security property is unchanged: the gated relay never reaches a recipient.)* Two properties no surveyed system has:
- *You can't lie in a field you don't fill* — the observable fields are conductor-filled, removed from the lane's writable surface.
- *You can't forget the check that is the gate on the door* — no clean observation, no relay leaves.

**Two pre-flights compose, order fixed** (matches m-1 §5 / m-2 §4): (1) **m-2 form-validation** (structure), then (2) **m-3 observe** (observable done-predicate). The bounce names which pre-flight failed. Running observe *inside* the atomic `submit()` closes the check→edit→send-stale TOCTOU: the observation that passed is the observation stamped.

**Trigger ≠ execute is load-bearing.** If the agent ran the probe itself, the result would be lane-forgeable again. The agent triggers; the conductor executes from its outside-lane vantage and returns the real result — seen-by-agent (so it self-corrects, no submit-blind churn) AND lane-**unsubstitutable** through the tool surface (confusion-resistant; D5 ground-truth residual, §11).

## 3. The observe-gate API surface (observer-only against the locked R3 allowlist)

```text
observe_gate(record_candidate, seat, phase, authority, evidence_target,
             artifact_refs, executable_claims, egress_targets, archetype_tags)
  -> observe_result {
       predicate_result:   pass | fail | blocked | degraded
       veto:               none | block_delivery
       observed_fields:    { closed m-3 system/computed set, per §3.1 }
       achieved_evidence:  E0 | E1 | E2 | E3 | E4          # conductor fact
       target_gap_result:  met | target_gt_achieved | not_applicable
       evidence_integrity: per-field { observed | self_reported }   # locked R3
       record_integrity:   observed | self_reported | mixed         # computed rollup, §6
       executable_claim_results: per-claim { pass | fail | skipped | unsafe }
       egress_scan_result: pass | blocked | not_applicable          # §7
       degradation_notes:  bounded-observation floor / truncation / backoff
     }
```
(Signature adopted from the reconciled m-3.implementer pass, `c2-audit-m-3/AUDIT-implementer-20260629-185327.md`.)

**§3.1 — the closed write-allowlist (R3 observer-only).** The hook writes ONLY: `ACTIONS_GIT_REF`, `FINAL_GIT_STATUS_SHORT`, `achieved_evidence`, the `target>achieved` computed `*_RESULT`, per-field `evidence_integrity`, the computed `record_integrity` rollup, the per-claim `executable_claim_results`, the `egress_scan_result`, `degradation_notes`, the routing-profile observed set (§9), and a pass/fail **veto**. It writes **no** identity/envelope field (FROM/ROLE/PARENT/relay_id) and performs **no** delivery effect. "Observer-only" is enforced as a positive allowlist, not prose intent.

**§3.2 — what may veto.** Delivery gates on *evidence integrity* **only class-conditionally** (operator decision ②, folded `c4-cq-gateconfig`): for a **non-authority** record a `self_reported` field still delivers — the honest fallback, §8 — but for the **authority/merge (A-gate) class** a not-fully-verified record (`record_integrity ∈ {self_reported, mixed}`) is **held/escalated, not delivered** (condition (d)). The vetoing/holding conditions are: (a) a phase-shaped done-predicate the conductor can observe to be **false** (e.g. an action-claim with no matching git ref; a read-only report over a dirty tree); (b) the generic **declared-vs-observed integrity veto** (a lane-declared field contradicted by conductor observation — e.g. clean-tree-claimed/dirty-observed; the routing silent-deviation case, §9); (c) a failed **egress** scan (§7); (d) **class-conditional fail-closed (decision ②):** `authority_class == true ∧ record_integrity ∈ {self_reported, mixed}` ⇒ the record is **held/escalated** (terminal `held`, resummon the operator — J1 `hold_and_resummon`), never shipped on a not-fully-verified authority claim. `authority_class` is m-2's declared key (`bool`·`owner:system`·`computed_result`, m-2 §17.6 — `record_kind ∈` the authority-bearing set **or** `gate_category ∈ A`; **never keyed on model**, R2 holds). Token mapping (CQ-4): (a)/(b) are the check **running and saying no** at acceptance ⇒ terminal **`rejected`** (§2); **(c) a failed egress scan is evaluated ONLY at the OUTBOUND external-send chokepoint (§7, m-6 §50/§51) ⇒ the non-terminal `egress_blocked` park + A local resummon — never a terminal token (not `rejected`, not `held`)**; (d) is the check **unable to fully verify** an authority-class record ⇒ terminal **`held`**. *Deviation-as-such* and *integrity-labeling-as-such* still never act; only silent-deviation (b) and authority-class not-full-verification (d) do.

**§3.3 — total observe→terminal disposition (m-3-F6; keyed by authority class).** Every submit reaches exactly one terminal `{accepted | rejected | held}` (m-7 §6 / NF-S16, exactly-one-outcome). The `observe_result` sub-enums are **observe-layer signals, not independent terminals**: `executable_claim_results` and `degradation_notes` feed `record_integrity`/`achieved_evidence`, they do not map to a terminal token directly. The total map (realizing the VP two-axis, `DESIGN-REREVIEW-2026-07-02` §5):

| observe condition | non-authority | authority-class |
|---|---|---|
| `predicate_result=pass`, `veto=none`, `egress=pass/n/a` | `accepted` | `accepted` |
| `predicate_result=fail` (check **ran, observably false**) or `veto=block_delivery` from a declared-vs-observed contradiction (§9) | `rejected` | `rejected` |
| `predicate_result=blocked \| degraded` (**no vantage** — opaque lane, §8; ⇒ fields `self_reported`/`mixed`) | `accepted` + `self_reported`/`mixed` label | **`held`** + escalate (§3.2(d): `record_integrity ∈ {self_reported, mixed}`) |
| **conductor check machinery ran-and-broke** (internal fault — m-7 §6) | `rejected` / author-returned, fault edge named | **`held`** + escalate |
| `egress_scan_result=blocked` (§7, outbound away-mirror) | *non-terminal* **`egress_blocked`** park + local resummon (m-6 §4 / m-7 NF-S9) | *(same — non-terminal)* |
| `executable_claim_results ∈ {skipped, unsafe}` | *(not a terminal — marks that claim's field `self_reported`; the record's terminal follows `record_integrity` per the rows above)* | *(same)* |

The two axes: **check-ran-said-no ⇒ `rejected`** (both classes); **check-could-not-run** (no vantage *or* machinery-broke) **⇒ authority `held` / non-authority `accepted`+label or `rejected`+fault-edge**; an outbound **egress-block ⇒ the non-terminal `egress_blocked`** park + A local resummon (m-6 §50/§51 / m-7 NF-S9 / ARCHITECTURE :309-310), **not a terminal token** (not `rejected`, not `held`). Egress is evaluated **only** at the outbound external-send chokepoint (§7, dormant until away-mode); the acceptance-stage `→ rejected` conditions are the predicate-false / declared-vs-observed integrity (a)/(b) vetoes, **not** egress. Consistent with CQ-4 (`c4-cq-gateconfig`), decision ② (§3.2(d)/§8), m-6 §2:46/§50/§51, m-7 §6/NF-S9, and ARCHITECTURE :309-310.

## 4. The evidence ladder + the check-registry (executable claims)

**The ladder is observation depth, not a separate system.** `EVIDENCE_TARGET` = agent intent (an `agent_enum_pick` over {E1..E4}); `achieved_evidence` = conductor fact; the gap is auto-flagged as the computed `target_gap_result` (the routing analog of which is §9). The conductor derives:
- **E1** — read the cited `file:line` / schema / static source.  *(passive; initial release)*
- **E2** — run a named local check: the test suite, lint, typecheck, a fixture.  *(initial release; see registry)*
- **E3** — integration/runtime check (local stack, worker, DB/API).  *(incremental)*
- **E4** — deployed/live proof — stays the explicit **LIVE-VERIFY** gate, often operator-observed (mirrors the upstream "merge is not deploy; deploy is not live verification," `protocol.md:202`). **Operator-attested E4 (m-3-F5):** when the operator — a trusted observer *outside* the lane — confirms live proof the conductor cannot itself derive, the per-field `evidence_integrity` stays the locked **two-value** enum (R3 not reopened); the record carries a **separate provenance marker `attestation_source {conductor | operator}`** (NOT a third integrity value). An operator-attested field is trust-equivalent to `observed` (a trusted outside-vantage), distinguished only by `attestation_source=operator` for honest audit — never `self_reported` (the lane did not assert it). Build-step definition, §13.

**The check-registry (resolves grill Q1, §12).** Every check the conductor runs is a **vetted, conductor-implemented, parameterized procedure** the agent *selects*, never code the agent *supplies*. An "executable claim" = the agent declaring "claim X, verify by registry-check C(params)"; the conductor runs *its own* implementation of C → "the conductor ran the check, it passed." **Arbitrary agent-*supplied* code is rejected** — the conductor is the TCB; the agent never selects arbitrary code, only a vetted registry entry. **Honest scope (m-3-F1 / x1-F5):** several suite-class entries (`run-suite`, `red→green-differential`) nonetheless **execute repo-resident lane code** (the project's own test suite *is* lane/repo code) — this is repo code the conductor *runs*, not conductor code, and not agent-*supplied* code. That execution is a **named non-locking carry** (§13): suite-class entries must run in an **unprivileged executor with no store / config / outbox handle and no signing key**, gating the Step-2 observe (E2) build; the paired executor-isolation fixture is **m-7-hosted** (NF-S6-analogue). Consequences:
- **One mechanism unifies executable-claims with the m-5 archetype gates** (§5): the archetype invariants *are* registry entries (`run-suite`, `find-references`, `diff-shape`, `red→green-differential`, `test-files-unchanged`).
- **The initial release ships the base conductor-owned checks active** (read-file, git-status, run-named-suite). Checks with **side effects or unbounded cost** run only under an **operator gate** (operator policy on which registry entries may auto-run). The registry is the **additive extension point** — new entries are an additive schema bump, not a new subsystem.

## 5. Per-phase done-predicates + the archetype-tag parameterization (m-5 seam — RESERVED)

**Base predicates are phase-shaped** (conductor-observable):
- read-only (AUDIT/DESIGN/RECONCILE report): allowed relay artifact present + **no unauthorized source actions** (clean/expected tree).
- IMPL: expected diff/artifacts exist + required checks green + **scope observed as `diff_paths ⊆ scope_paths`** where `scope_paths` is a plan-declared named form field (named owner). *(m-3-F7: a bare "no scope drift" with no declared `scope_paths` field is **struck** — not conductor-observable — rather than asserted; the observable form is the declared-path-subset check, a build-step dependency on m-2 declaring `scope_paths`, §13.)*
- MERGE / LIVE-VERIFY: the target merge-commit / deploy / live proof exists, as applicable.

**Archetype add-ons parameterize the predicate via the opaque `slot_in` atom.** The done-predicate hook takes an opaque archetype-tag input that *selects* an invariant-set. **m-3 owns the predicate-execution mechanism + result shape; m-5 owns the tag-space + which invariants attach to which tag.** Candidate mappings **surfaced, not closed** (per VP c2-decomp Finding 4):

| archetype | observable invariant | registry check |
|---|---|---|
| extension | additive-only diff + suite-green, **zero test-edits** | diff-shape + run-suite + test-files-unchanged |
| refactor | suite-green **AND test-files-unchanged** | run-suite + test-files-unchanged |
| cleanup | find-references = 0 | find-references |
| bugfix | repro **red on parent SHA → green on fix** + suite-green | red→green-differential + run-suite |
| migration | reversibility (existing prod-risk tier) | (m-5/existing tier) |

The two **observer-selected** invariants (refactor no-test-edits; bugfix red→green) — *confusion-resistant*, not tamper-proof (§11 claim boundary) — are load-bearing: the reward-hacking evidence (audit §A) shows "edit the tests to keep green" and "hardcode the expected artifact" are exactly how an in-reach verifier is gamed; these invariants are the defense, selected conductor-side and conductor-observable. (They are heuristics, not proofs — red→green proves a *differential*, not that the repro exercises the bug; the semantic-gameability caveat is the `DESIGN-REVIEW-2026-07-01` SHOULD-FIX, tracked separately.) **Lock prerequisite:** the c2 lock carries an explicit reservation preserving m-5 ownership of the concrete tag-space + archetype invariants (+ with m-4 the authority-ceiling semantics); m-3 locks ONLY the predicate-execution mechanism keyed on the opaque tag.

**§5.1 — `slot_in` provenance + axis (folded per `c2-fold-m-3`, additive).**
- **F1 — conductor-owned, classified AT WORK-RECORD ACCEPTANCE, immutable, non-lane-writable.** The work-archetype tag `slot_in` is **filled by the conductor** — the already-reserved m-2 opaque `slot_in` atom, with its filler selected as the existing **`system`** field-ownership category — and **classified at work-record acceptance**, immutable thereafter; it is **never lane-writable**. This is the **confusion-resistance** the observe story depends on (observer-selected: the invariant is chosen conductor-side and the observed lane has no *tool* to rewrite the classification; not tamper-proof against the D5 same-uid direct-store-write residual, §11): were a lane able to set its own work-archetype through its tool surface, it could re-tag `refactor`→`extension` to escape the no-test-edit invariant, or `bugfix`→other to escape the red→green differential — the exact reward-hacking failure §5 / audit-§A defends against. *Per VP pin:* classified **at work-record acceptance**, NOT stamped from the seat's spawn-time binding — spawn-derivation would wrongly forbid a long-lived seat from doing bugfix→refactor→migration over its life; the load-bearing invariant is **non-lane-writability + immutable conductor classification**, not spawn-derivation. (The exact pipeline point is **pinned by CQ-5** (`c4-cq-slotin`, co-signed): the conductor classifies `slot_in` at work-record acceptance **post-form/lineage-gate, PRE-observe-hook, binding atomically with the observation** — so the Step-2 done-predicate reads the just-classified in-courier `slot_in`. This is *required*, not merely chosen: the observe hook **reads** `slot_in` to select the invariant but **does not write it** (§3.1 allowlist excludes `slot_in`), so a distinct conductor step must set it pre-observe. The immutability-after-acceptance + non-lane-writability enforcement remain PLAN details, §13.)
- **F3 — `slot_in` = the WORK-ARCHETYPE axis ONLY (per work record).** The done-predicate hook keys on `slot_in` = work-archetype, per-record. The orthogonal **seat-archetype** axis (`seat_archetype`, per-seat-at-spawn) is a **separate opaque tag owned outside m-3** (m-4's routing vector, per `c2-fold-m-3`); m-3 does **not** absorb seat / ceiling / authority semantics into `slot_in`. *(De-lock note, per the c2-lock review `RECONCILE-orchestrator-reviewer-20260630-042313`: any archetype values named anywhere in this doc — e.g. a `refactor` work-archetype, a `sensor` seat-archetype — are **non-locking candidate vocabulary inherited from the surfaced consumer-review table, NOT Step-1 locked values**; the concrete tag-space + invariant selection + ceiling semantics stay m-5-owned, c3. Applied by master.orchestrator-planner under operator direction — a non-substantive textual de-lock, not an m-3 design change.)*
- **Bounded (VP guardrail):** `slot_in` stays **opaque** — no concrete Step-1 values, no `required_when`/`visible_when` branch on concrete slot values, no change to m-2 ownership categories or the bounded predicate vocabulary; the concrete tag-space + invariant selection remain **m-5-owned (c3)**. Selecting the filler as `system` picks an existing m-2 category and does not alter m-2 (pre-authorized by the fold dispatch).

## 6. evidence_integrity — per-field truth + the computed audit rollup (resolves grill Q4)

- **Per-field `evidence_integrity {observed | self_reported}` is the only canonical integrity truth** — locked R3, two-value, NOT reopened. Set by the conductor per observed/computed field: `observed` when the conductor derived the value from outside the lane; `self_reported` when it could not and the lane supplied it.
- **`record_integrity {observed | self_reported | mixed}` is a conductor-computed rollup**, stamped onto the immutable record for **human auditability** (and the Owner Decision Brief). It is a **pure function of the per-field stamps** — `observed` if all expected-observable fields are observed; `self_reported` if none are; `mixed` otherwise — so it can never drift from or be forged independently of the per-field detail (the auditor sees exactly what the conductor derived, frozen). It is **system-computed**, not a new agent-writable field; canonical-iff-consumed is satisfied (the audit/ODB surface is the consumer).
- **Safety rule:** anywhere a trust/gate decision reduces the label to yes/no, **`mixed` is treated as not-fully-verified** (pessimistic for trust, informative for audit). No mechanical *delivery* gate branches on either label **for non-authority records** — integrity is labeled, not gated. The class-conditional exception (operator decision ②, §3.2(d)/§8): `authority_class == true ∧ record_integrity ∈ {self_reported, mixed}` ⇒ `held`/escalate — the disposition keys on m-2's declared `authority_class`, never on model (R2). *(The `mixed` leg is the VP-ratified **CQ-2 canonical** resolution of the edge this doc previously left open for the now-closed m-2/CQ-4 co-sign: per this section's own pessimistic rule (`mixed` = not-fully-verified anywhere a trust decision reduces to yes/no), a partially-verified authority record **holds** rather than delivers, consistent with §3.2(d)/§8. This widens the m-3 **disposition** only — `record_integrity` already ranges over `mixed` (m-2 §17.6), so m-2's field-home is unchanged; convergence assumes the parallel c6 token-alignment in m-2 §17.6 / m-7 §15 / ARCHITECTURE C4.2.)*
- **Scope of the claim (m-3.implementer carry-forward):** `record_integrity: observed` means **every declared-observable field was observed** — it is NOT a claim that free-text judgment / agent rationale is independently verified. Per the locked boundary (observable → system-captured; judgment/unobservable → agent-asserted + cross-lane reviewed), prose judgment stays agent-asserted and review-gated; `record_integrity` ranges only over the observable field set. (Fixture in §13.)

## 7. The egress / content-safety gate (resolves grill Q2)

**A fail-closed scan at the conductor-governed egress chokepoint.** The conductor's local outbox is the **only egress the governance system offers** (a governance-surface claim, **not** a system-level sole-egress claim): destination control over that governed path is by-construction (post-spike), so a pre-external-send scan on it cannot be skipped *through the governed surface* (vs agent-scripts' own `cmd_force_send` hole, `openclaw_relay.py:676-719`, which sends without a scan). The scan inspects the outbound body + attached/generated proof artifacts for **secrets / PII / undisclosed-model-names / auth-URLs**; that **content** safety (regex/entropy) is **best-effort and encoding-evadable — not "structurally unbypassable."** D5 residual (§11): under same-uid attach a shell-bearing seat can reach the network outside the conductor entirely (host Bash/curl); the egress gate vouches only for the governed outbox.

- **Policy = always-block + hold-and-resummon (operator decision, §12).** Any flag ⇒ **block, never auto-send**; park the gate and resummon the operator (aligns with locked J1 `hold_and_resummon`) — this park is the **non-terminal `egress_blocked` state (§3.3), NOT the terminal `held` token**; egress is never a terminal outcome (m-6 §50/§51). **No auto-redact** in the default; auto-redact is available only for content classes the operator *later explicitly whitelists*.
- **Rule set is operator-configurable policy** (mirrors locked §J2 `gate_category` config-sourced pattern) with a fail-closed `other`→block default. **Promote, do not rebuild** the detection engines: agent-scripts `agent-transcript:193-235` (redact/unsafe/fail-closed) + claude-code `secretScanner.ts:277-324`; for model-name disclosure, claude-code `sanitizeModelName`/`isInternalModelRepo` (`commitAttribution.ts:114-168`).
- **Decision-⑤ carve-out — narrow, typed ODB model-name confidentiality exemption (operator decision, §12; folded `c5-fold-decision-5`).** The scan distinguishes two classes: **confidentiality** (undisclosed model-name disclosure → peer-bias — R2's rationale) and **safety/content** (secrets / PII / auth-URLs). Decision ⑤ exempts **exactly one typed field** from the **confidentiality class only**: `record_kind == ODB` (operator-facing, **conductor-generated**) ∧ `field == model_name` (m-6's typed **exempt-marked** ODB field) ∧ `destination == operator`. **Everything else is unchanged** — model-names still block on every other record / field / destination; the **safety/content** class still fully scans the ODB (a secret / PII / auth-URL in *any* ODB field still blocks); the fail-closed `other→block` default is preserved on all other paths. **Confusion-resistant, not forgery-proof (c5 checklist; D5 residual §11):** the exemption is reachable **only** through the governed ODB render/scan surface — the field is conductor-generated and **non-lane-writable via the tool surface (§3.1)**, so a *confused* lane has **no tool** to mark arbitrary bytes as the exempt model-name field (which would otherwise be a confidentiality-scan bypass).
