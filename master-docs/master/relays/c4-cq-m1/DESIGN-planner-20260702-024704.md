### (ii) The step-gate FieldSpec expression
An observe-owned field F's **effective** required predicate is:
> `all_of( required_when(F), layer_present:observe )`

where `layer_present:<layer>` is a **new bounded, closed context atom** (`<layer> ∈ {store, form, lineage, observe}`, §5) the courier evaluates from which fill-layers/writers are bound at runtime. **Step-1 binds `{store, form, lineage}`; `observe` binds at Step-2** — so in Step-1 `layer_present:observe == false` ⇒ F **not required**. A form gate can therefore never demand a field nothing can fill (the fill-time-authority principle: a required field must be fillable).
- **Derivable-from-typing, not a bespoke hack:** because these fields are `owner:system` + `fill_constraints: observed_value` (or a `*_RESULT`/rollup computed from observed values), they are **observe-layer-filled by construction** — the `layer_present:observe` conjunct makes explicit what canonical-iff-consumed already implies (don't require an unfillable field).
- **Bounded/decidable + R2-safe:** `layer_present` is a finite closed context predicate (same class as `phase_in`), no loops/calls; it references **build-layers, never model** — R2 untouched.

### Confirming m-1's hard guardrail (the load-bearing half of (a))
**The step-gate applies ONLY to observe-owned fields.** Every `system_only` / lineage / form-owned required field stays **fully required in Step-1** — the `layer_present:observe` conjunct is attached *only* to the observe-owned set above, never to identity/envelope/lineage/form requireds. The step-gate is **not** a lever to relax non-observe requireds. (This is why m-1 rejected (b) conductor-side filler: a Step-1 filler would either be the reserved Step-2 DI-5 read or fabricate evidence — the step-gate instead makes the field *honestly absent* in Step-1, not falsely filled.)
