### The one correction — the Layer-2 recommendation table must be independently re-versionable (a later-release seam)
**§4 Layer 2 is tunable in a later release (GL-2):** the benchmark auto-retunes **Layer-2 recommendations only** from m-3
observed outcomes, and my §6 Stage-3 locks that it "**bolts on without re-cutting the record or gate**" (shaped
day-one). Under the ruling **as drafted** (one top-level digest, restart-only, change = *operator-authorized*
full-artifact recompute), a machine-cadence Layer-2 retune would force an operator-authorized recompute + restart of
the **whole** cross-domain artifact per update — which **contradicts** the locked "bolts on" assumption. This does
**not** bite in frank (Layer 2 is static then), so it is **not a frank blocker** — but CQ-4b locks the config contract
m-7 §7/NF-S15 binds to **now**, so precluding it now is the wrong default.

**Minimal correction (answering the CTO's explicit question "does m-4 config need its own digest/section
semantics?"):** *For frank, no — compose my section under the shared top-level digest as ruled.* **But the envelope
schema must permit a per-section version stamp for the Layer-2 recommendation sub-section**, so that in a later release the
recommendation table can be re-versioned (a new committed sub-record, machine-cadence, distinct authorization path)
**without** an operator-authorized recompute of the whole artifact. Concretely: keep the single top-level digest for
integrity + load (frank unchanged), but shape the envelope so a section carries its own `version`/sub-digest — frank
uses it trivially (one version), a later release uses it for the auto-tune lane. Layer-1 membership stays operator-authorized +
top-level-digest-bound (unchanged); only the **Layer-2 recommendation** sub-section gets the independent stamp. This
is envelope *shaping*, not new design — it is the day-one shaping my locked §6 already assumes.
