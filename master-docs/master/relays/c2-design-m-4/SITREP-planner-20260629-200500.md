### The directive (operator, verbatim intent)
**Step-1 ships with a small collection of selectable team templates (ship 1–3). The user picks one and the conductor spawns the team — opening the panes/sessions, each named for its seat and started with its preset model, awaiting input.** Operator scoped this as **option B**: ride existing runtimes (the conductor materializes + opens the templated setup; it does NOT need its own provider-adapter runtime). Operator explicitly **left the template structures + the shipped lineup to m-5**.

### What m-4 absorbs (designed now in `c2-design-m-4-routing-policy`, no roadmap change for this part)
A **routing template** = a saved, named, reusable set of per-seat model assignments — each **pinned** (exact model) or **slot** (a capability-bucket the router fills at spawn), mixable, operator-customizable. On template-spawn, m-4 emits the `routing_decision` record for the team (pinned filled directly; slots resolved via the capability priors). This is a clean extension — a template is just a **reusable routing decision**; it does **not** change the locked c1 contract or R2 (model stays payload; the template is a pre-filled record, not a gate input). The bucket layer (Q1 grill-lock) makes slots churn-stable. m-4 ships the **model-assignment side** of the 1–3 templates; m-5 owns their structure.

### Cross-domain + roadmap parts flagged for CTO/VP arbitration (NOT m-4's to decide)
1. **m-5 — template structures + lineup.** The seats/panes that exist per template, the gate-set, read-only-ness, and the shipped 1–3 lineup are m-5 archetype-presets. The operator left these to m-5. This **pulls a slice of m-5 forward into Step-1** (the roadmap currently has m-5 at Step-5).
2. **Conductor-core (m-1 / Step-1) — the spawn capability.** Opening + naming the panes/sessions + delivering boot relays from a template is a Step-1 **spawn capability**. It is lighter than Step-3 (no provider adapters — it rides the existing runtime's session/pane creation + model flags), but it is a new Step-1 capability beyond "record + relay."
3. **Roadmap.** "Select-template → team spawns" is a Step-1 scope addition spanning **m-4 (model presets) × m-5 (structure presets) × conductor-core (spawn)**. It is consistent with Step-1 = "automated operator-relay" (option B, no own-runtime), so it does **not** pull Step-3 routing-execution forward — but it does pull a slice of m-5. Recommend the roadmap fold this as an explicit Step-1 deliverable with the cross-domain decomposition named.
