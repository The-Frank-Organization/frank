## 2. The check-registry model (locked §4, realized)

**An entry is a vetted, conductor-implemented, parameterized procedure the agent *selects* — never code the agent *supplies*** (§4). An **executable claim** = the agent declaring `(claim_ref, check_id, params)`; the conductor runs *its own* implementation of `check_id` and records the typed result. Arbitrary agent-supplied code is rejected (§4; the conductor is the TCB).

**Entry descriptor (design shape; maps onto the existing `obligation.Class`-style registration pattern, not a new subsystem):**
```text
CheckEntry {
  id:               string                    # stable, the agent selects by this
  rung:             E1 | E2                    # the max evidence rung a pass reaches
  class:            base | suite | side_effecting
  executor_required: bool                      # true ⇒ runs in the m-7 unprivileged executor
  param_schema:     { … typed params … }       # closed, conductor-validated
  produces:         [ observe-field ids it feeds ]   # never writes them — feeds the conductor, §6
  timeout_class:    read_short | suite_bounded # hard wall-clock; §4
}
```
`class` drives isolation + gating: **`base`** runs in-process in the conductor (read-only, no repo-code execution); **`suite`** executes repo-resident lane code and therefore **must** run `executor_required` in the m-7 unprivileged executor (§4/§13 honest scope — "repo code the conductor *runs*, not conductor code, and not agent-*supplied* code"); **`side_effecting`** is the default-denied class (§4).

The registry is the **additive extension point** (§4:90): a new entry is an additive schema bump (a new row in the registry table), never a new subsystem — consistent with the `s5` additive-row-is-MINOR classification (ignore-unknown).

## 4. Per-check hard timeout + the operator gate (component 2)

**Every check carries a HARD wall-clock timeout, conductor-enforced (it kills the executor subprocess).** Timeout is **fail-closed**: a check that cannot finish never yields a pass.

> **INTERIM — s10 SUNSET (operator ruling 2026-07-11, `step2-plan/SITREP-orchestrator-planner-20260711-025643`).** The numeric hard-kill defaults (**E1 ≤ 5s / E2 `suite` ~120s**) stand for **s8/s9 (testing-phase only)**, but the **silent** hard-kill disposition is interim. **At s10 the timeout path MUST gain the operator-in-the-loop shape:** a long-running check **alerts the operator with the decision (kill / extend)** via the s10 park + ODB + operator-verdict machinery, instead of dying silently; the hard ceiling remains as the **fail-safe backstop behind the prompt**. The exact composition (J1 no-hard-deadline posture vs a wedged submit) is a **named s10 DESIGN question**. This is a **NAMED s10 EXIT CONDITION** — s10 does not close while the silent auto-kill survives.

**On expiry the check is "machinery-could-not-complete," NOT "ran-and-said-no"** — so it takes the **§3.3 machinery-fault edge**, distinct from both the predicate-false `rejected` path **and** the no-vantage degradation row:
- `predicate_result = blocked | degraded` (the check machinery started and was killed / could not run to completion) →
- **authority-class → terminal `held` + escalate** (§3.2(d)); **non-authority → terminal `rejected` / author-return, the fault edge named.** This is the locked §3.3 "conductor check machinery ran-and-broke (internal fault — m-7 §6)" row (`…2026-06-29…:72`), applied to timeout/process-kill; it matches the kickoff two-axis disposition (`STEP-2-KICKOFF.md:47` — "observe-machinery internal fault/timeout: authority → `held`, non-authority → `rejected`/author-return; never conflate no-vantage with machinery-fault").
- **`accepted` + `self_reported` is NOT a timeout/machinery-fault outcome** — it belongs *only* to the separate **no-vantage / opaque-lane** degradation row (§3.3:71), where the conductor had no vantage at all rather than a check it started and killed. A killed check is a fault, not a missing vantage. *(r1 correction, m-3.implementer F1.)*

**§4a — the `read-file` in-process E1 read mechanism (s8-row2, Option 2′; LABEL == MECHANISM; supersedes master's r7 "an ACTUAL ≤5s wall deadline over blocked I/O" wording; r2 folds m-3.implementer F1/F2/F3).** A real wall deadline *over a blocked file syscall* is **not enforceable in-process on this platform** (contexts do not cancel blocked file I/O; `ErrNoDeadline` on ordinary files; even `SIGKILL` cannot reap uninterruptible D-state) — so the r7 label overclaimed. `read-file` stays **`class: base`, in-process, no executor (§3 boundary preserved)**; the ≤5s ratified-interim deadline is enforced by a **two-part guarantee split at the confusion grain**:
- **Part A — race-safe rooted confinement + lane-reachable wedge refusal, by construction (F2):** confinement is proven by the **opened descriptor**, never a pre-open resolved pathname (resolve-then-open is a TOCTOU gap a lane can win). Use a **race-safe rooted open** — **descriptor-relative component traversal with no-follow semantics from the governed lane-root fd** (`openat2 RESOLVE_BENEATH`/`RESOLVE_NO_SYMLINKS`-class, or the portable dir-fd-relative `O_NOFOLLOW` walk) — so the opened fd is provably **beneath the governed root**; then **`fstat` on that fd, regular-file-only**. Absolute/`..` refusal and symlink-escape rejection are preserved; a **lane-creatable FIFO / socket / symlink-to-nonregular is refused typed** (`not-regular-file`, path-free) **without a blocking read**. *(Boundary stated precisely: lane-creatable special files are refused pre-read; a pre-existing/privileged device node or a stalled mounted filesystem is the operator-topology residual (Part B) unless the rooted open rejects it before a potentially-blocking device open.)* Then **chunked bounded reads with a between-chunk ≤5s deadline check + a byte ceiling** ⇒ a large regular file is refused typed (`read-deadline-exceeded` / `read-size-exceeded`) before it stalls. **The byte ceiling (F5)** is an **m-3-owned concrete s8 constant** (`readFileByteCeiling`, default **8 MiB** — ample for any cited E1 artifact/schema, far below a stall; a candidate to promote to a governed config field later, alongside the §9 operator-owned timeout numerics), enforced against **BOTH the initial `fstat` size (rejected pre-read if `size > ceiling`) AND cumulative streamed bytes (rejected mid-stream)** so a growing / sparse / special file cannot bypass it. The ceiling is a **durable fail-closed resource bound — NOT part of the s10 sunset** (only the *silent-deadline* behavior sunsets; the finite byte ceiling persists). Boundary fixtures at **exactly-ceiling / ceiling+1 / growth-beyond-ceiling**, errors symbolic/path-free.
- **Part B — the ENTIRE filesystem transaction is behind the detachable boundary; the kernel-blocked residual is OPERATOR TOPOLOGY (D5-class), STATED (F1):** on a stalled FUSE/network mount, **rooted resolution/traversal, `open`, `fstat`, every read chunk, and close/cleanup** may each block in un-interruptible D-state — so **all of them run in the detachable worker**, not only `read()`. The **serialized commit loop performs ONLY** non-filesystem state checks → launch the worker → wait on a **buffered completion channel vs the ≤5s deadline** → **atomically trip the breaker** → **RETURN the typed machinery fault**. It touches **no filesystem syscall itself**, so the single commit path **never wedges** (→ the §4/§3.3 machinery-fault edge, authority `held` / non-authority `rejected`). The detached worker on a stalled operator mount is the **residual, STATED beside D5** (§11) — you cannot reap D-state; that is the operator's topology, not lane input, never described as eliminated or reapable.
- **Breaker lifecycle (F3):** breaker **check/set is owned by the single serialized commit-loop**, **set-before-return** (so a second worker for that lane cannot launch after the timeout). Bound = **at most one detached filesystem worker per governed lane, per serving process/registry instance** (total residue bounded by the finite governed lane set). A tripped lane refuses further `read-file` typed **for the lifetime of the serving process; reset only after operator remediation + confirmed process replacement** (a D-state worker may not exit promptly / may retain locks — a **failed restart/process-exit is itself part of the stated operator-topology residual**, not a claimed recovery). A different lane stays independently usable. **Breaker-open is an EXPLICIT machinery fault, NOT a generic refusal (F4):** the refusal carries the conductor-classified reason **`check-machinery-read-file-breaker-open`** with **`MachineryFault: true`** at aggregation — so it takes the §4/§3.3 **machinery-fault edge** (authority **`held`**+escalate / non-authority **`rejected`**/author-return), **never** the no-vantage `accepted`+`self_reported` path (a lane whose read-file path just timed out is *known-unhealthy*, not un-observed — this is the §12(g)/F4 explicit-signal rule applied here). The bounce is path-free/I-PH-safe; no worker launches.
- *(Fits Rail B: a spawn-helper surface would be justified mainly by an operator-controlled input class, so no new TCB surface is warranted inside the serialized path; Option 1's killable helper is rejected — it pays a new production protocol + a per-check spawn in the serialized path for zero-strand purity it cannot deliver against D-state either.)*
- **Fixtures (§8):** FIFO/socket refusal + large-file ceiling = mechanically **probative (RED-first)**; a **race fixture** swaps a checked component toward an outside regular file and proves **no outside bytes are read** (F2); the **detach** leg is proven through an **injected blocking seam that can block at before/open/metadata/read** (not only a synthetic reader), claim text = "the control path returns for a blocked filesystem operation" at that seam grain (F1); the **breaker** leg proves a second same-lane call is refused **without launching another worker** while a different lane remains usable (F3), **and asserts both authority-class terminals + the exact `check-machinery-read-file-breaker-open` fault class** (F4); the **byte-ceiling** leg pins **exactly-ceiling / ceiling+1 / growth-beyond-ceiling** against both `fstat` size and streamed bytes (F5). All errors symbolic/path-free. No 1ns-polling pretense.

**The side-effecting classification + the operator gate (§4:90 / §12).** A check is **`side_effecting`** if it may write outside the executor's ephemeral workspace, open the network, or has unbounded cost. `base` and `suite` checks are **not** side-effecting-beyond-workspace — the suite runs in the isolated ephemeral executor and its writes are confined to the **per-run workdir, the only writable surface the host provides** (that confinement is m-7's executor guarantee, §7; it holds at the **provided-surface** grain, with the same-uid ambient residual **stated**, never "by construction" — the F4 scoping, §5/§11). **`side_effecting` entries are DEFAULT-DENY**: they never auto-run; each requires an explicit per-entry operator allow. ## 6. Verdict → conductor-computed-field binding (component 4)

**The executor returns a TYPED VERDICT ONLY and writes NOTHING to the record:**
```text
CheckVerdict {
  check_id, claim_ref
  outcome:      pass | fail | skipped | unsafe    # the §3 executable_claim_results enum
  rung_reached: E1 | E2 | none
  predicate:    pass | fail | blocked | degraded  # the §3 predicate_result enum
  timing, failing_detail
}
```
The executor **has no store handle** (§7) and **no entry in the §3.1 write-allowlist** — so a verdict that *claims* to have written a field is **inert**; only the conductor writes fields.

**The conductor (the observe hook, inside the atomic `submit()`, §3.1) consumes the typed verdict and computes:**
- `executable_claim_results` ← one row per claim `{ claim_ref, check_id, outcome ∈ {pass|fail|skipped|unsafe} }` (§3.1-allowlisted).
- `achieved_evidence` ← the **max rung actually *reached* by a passing check** (E1 if a read-check passed; E2 if a suite check passed) — a **conductor fact**, not agent intent.
- `target_gap_result` ← compare `EVIDENCE_TARGET` (agent intent, already live + always-required, s5) vs `achieved_evidence` → `{ met | target_gt_achieved | not_applicable }`.
- The verdict drives `predicate_result`/`veto` → the **§3.3 terminal token** `{accepted | rejected | held}`: `pass` + `veto=none` → `accepted`; `fail` (ran, observably false) → `rejected` (both classes); `blocked|degraded`/timeout (machinery could not run to completion) → the §4 **machinery-fault edge** (authority `held`; non-authority `rejected`/author-return, fault edge named — **never** `accepted`+label, which is reserved for the separate no-vantage row §3.3:71); `outcome ∈ {skipped, unsafe}` → **not a terminal** — it marks that claim's field `self_reported` and the record's terminal follows `record_integrity` (§3.3:74). A `side_effecting` check with no operator allow returns `unsafe` (refused) → that claim's field `self_reported`.

**Load-bearing (§2 trigger≠execute + §3.1 observer-only):** the agent **selects** the check; the conductor **runs** it and **stamps** the fields; the executor sits **outside** the allowlist. So the result is conductor-derived and **lane-unsubstitutable through the tool surface** (confusion-resistant; the D5 direct-store residual stands, §11).

**§6.1 — I-PH: the check-param + verdict-output hygiene contract (m-3-owned).** Because m-3 hands m-7 the **closed param schemas + the `CheckVerdict` shape** (§7), the information-hygiene of those surfaces is **m-3's contract to pin**, not solely m-7 host policy. It holds the Step-2 I-PH sweep (kickoff:52) and the m-7 guardrail (no raw store/config/outbox/operator-channel/socket path and no effective config value in any seat-deliverable surface, `m-7 §125/§168`) across every new m-3 check surface:
- **Params are normalized + closed.** Every path param is normalized and **scoped to the declared `lane_ref` work-artifact root (or another approved evidence root)**; **absolute paths and `..` traversal are refused at validation**; `read-file.schema_ref` is a **registry id, not a path**; `run-suite.target` is a **named-suite enum drawn from the registry, never command text** (no shell/argv injection surface).
- **Verdicts / bounces / rows / `failing_detail` are path-free + bounded.** Raw store/config/outbox/operator-channel/socket paths and **effective config values never appear** in any `CheckVerdict`, bounce text, `executable_claim_results` row, or `failing_detail`. `failing_detail` is **symbolic, bounded, and path-redacted** — a failing test *name* / a symbolic predicate id, never raw command output or file contents.
