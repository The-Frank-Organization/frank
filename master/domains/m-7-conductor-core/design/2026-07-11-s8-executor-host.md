## §1 The claim, scoped exactly (F4, binding wording for every artifact and fixture)

Repo-resident suite code run by the executor **can** inherit ambient same-uid capability — filesystem, network, process spawning, toolchain caches — unless an OS sandbox exists. Therefore the designed claim is exactly:
1. **No conductor-governed mutation handles are provided**: the run surface contains no store/config/outbox/operator-channel handle, no seat credential, no signing material, and no canonical path text — proven by absence from inside (the §8.4 idiom at the executor context; the F6/F7/G(i–iii) grain).
2. **No writes to canonical conductor state through the provided surface**: the executor returns a typed verdict; it holds no write verb of any kind — verdict consumption happens in the serialized loop.
3. **The same-uid ambient residual is STATED, never engineered away by wording** (the D5 family): suite code could, via OS ambient authority, touch what the OS lets the uid touch. This residual is reported separately by the NF fixture and never labeled "by construction".
4. **OS containment is not claimed.** An OS sandbox (container/jail/seatbelt) is an operator-electable, separately-grilled addition (§5 durable question); if elected it upgrades enforcement, not the v1 claim's honesty.
Unqualified "never writes" / "fully isolated" wording anywhere in s8 artifacts is a design defect by this section.

## §2 The run contract — the eleven questions, resolved

1. **Snapshot/worktree identity (r2/F2: identity ≠ enforcement):** the **run manifest** `{check_id, check code version (the §7-pinned registry/catalog member version naming the check), declared input digests (content-hashes of candidate bytes + referenced evidence)}` immutably identifies the **pre-spawn bytes** — what was staged, provably, at spawn time. The staged COPIES are ambiently mutable by same-uid code after spawn (the §1.3 residual); no immutability of the copies is claimed. No live repo checkout is provided; suite code is staged into the workdir by the host from the pinned source.
2. **Working directory + writable policy (r2/F2):** one per-run `os.MkdirTemp` workdir is **the only writable surface the host PROVIDES**; inputs are staged inside it; `TMPDIR`/`HOME`/all cache variables point INTO it — **no shared per-executor cache exists in v1** (rejected: a second provided writable surface and a cross-run contamination channel; if build cost ever demands one, it is a design change with content-addressing/reset semantics and manifest-declared inputs — not a silent addition). Wording rule bound by this section: the design and every fixture say "the provided writable surface", never "the only writable surface" simpliciter or "writes confined" — the NF proves provided-surface facts; ambient writes are the stated residual. *(Reconcile flag for master: m-3's §4 sentence "its writes are confined there — that confinement is m-7's executor guarantee" inherits THIS scoping — provided-surface + stated residual — at reconciliation; I do not author m-3's text.)*
3. **Environment + descriptors:** child env is **allowlist-built, deny-by-default**: `PATH`, `TMPDIR`/`HOME` (→ workdir), the declared cache vars, and the check's declared inputs as explicit variables — nothing inherited wholesale; the design enumerates the final allowlist and the NF fixture pins it. Descriptors: stdin closed; stdout/stderr captured pipes; nothing else inherited.
4. **Credential/signing scrubbing:** no seat credential, mint material, or signing secret may appear in env, args, staged files, or the cache dir; FX-EXE-1 probes from inside; the loud failure is a red law-class check.
5. **Filesystem/store/config/outbox path exposure:** the I-PH families extend to the executor context — no canonical store/config/outbox/socket path text in env, args, staged inputs, or the manifest as delivered to the child. (The host knows the paths; the child surface does not.)
6. **Network + subprocess policy:** subprocesses are permitted (toolchains need them) and are contained by process-group discipline (Q7). Network (r3/F3): **network use is UNSANCTIONED by the suite-class declaration/policy — never claimed absent.** The executor provides no network handle or credential; ambient network access by same-uid code **remains possible and untested** without the operator-elected sandbox (a check declaring network need is not suite-class — m-3's registry face).
7. **Expiry disposition + descendant termination (r5, the accepted T9 amendment; r2/F4's state machine unchanged):** the child is spawned in its own process group (`setpgid`). **(r5) On expiry of the descriptor timeout, the disposition is `{kill, extend}` via park + ODB under m-6's J1 contract, with the monotonic hard ceiling as the block-only fail-safe backstop (it may kill with no operator response; it never extends); ANY kill — operator-verdict or backstop — runs the unchanged state machine (i)–(v).** On a kill (and on shutdown) the host runs, in order: **(i)** SIGKILL to `-pgid`; **(ii)** reap the direct child (`wait`) — the s7b CRASHPOINT-KILL-RETURN lesson: never proceed on kill-sent, only on exit-observed; **(iii)** **verify process-group death**: poll `kill(-pgid, 0)` until `ESRCH`, bounded (a fixed attempt/deadline budget, re-signaling each round); **(iv)** only after ESRCH: workdir cleanup and verdict disposition proceed; **(v)** if the bound expires with the group still live, the run becomes a **typed no-verdict machinery fault** routed to the outer NF-S6 edge, the workdir is PRESERVED (diagnosis, no cleanup under a live group), and the survivor pgid is reported — "no orphan" is never claimed from child reap alone. **Platform assumptions, stated:** POSIX process groups (darwin/linux — the supported set); the reap-before-verify ordering bounds the pgid-reuse window (the group id is not reused while the direct child is unreaped; the residual reuse risk after reap is noted, not hidden).
8. **Output/resource ceilings:** stdout+stderr captured under a byte ceiling; truncation is **marked, never silent** (the s4 frame-ceiling disclosure pattern); the typed verdict payload is size-bounded. No rlimit claims in v1 (an OS-tier control — §1 honesty); the ceilings that exist are capture-side and provable. **(r5, the accepted amendment's second sentence, also amending the supply-set leg's ceiling wording:) the descriptor `timeout_seconds` is the SOFT expiry bound (the prompt point); the J1 hard ceiling is the enforced maximum; spawn-time composition and class checks are unchanged.**
9. **Cleanup after timeout/crash:** workdir removal is host-owned and runs only after exit-confirmed reap (Q7); a run that dies mid-way leaves no partial verdict — "no verdict" is the outcome the outer gate dispositions (Q10). **All v1 cache content is run-scoped under the workdir and follows the full §2.7 cleanup state machine (r3/F1 — nothing survives a run); on a survivor fault the WHOLE workdir, cache content included, is preserved for bounded diagnosis.**
10. **Operator-gated side-effect semantics (r2/F1: aligned with m-3's APPROVED taxonomy):** m-3's registry defines `class: base | suite | side_effecting` with `side_effecting` default-denied under a static engine-config allowlist (`2026-07-10-s8-check-registry-probe-design.md:32-46,81-83`) — that taxonomy and its operator policy live in m-3's design and are NOT restated or altered here. **The v1 executor host accepts `spawn()` only for `class: suite` (read-only, `executor_required`) entries.** A `side_effecting` entry is refused upstream by m-3's conductor-side selection validation (their `unsafe`/refused path); if one nevertheless reaches `spawn()`, the host refuses it as a typed machinery fault — defense-in-depth, not policy (the policy seat is m-3's). The host exposes no operator-gate plumbing. A run failure/timeout surfaces to the observe gate as a typed no-verdict fault, dispositioned by **NF-S6's two-axis rule** — the executor adds no disposition authority of its own.
11. **Candidate-bytes→verdict binding (r2/F3+F5: the honest exactly-once claim + the RunResult/CheckVerdict split):**
    - **Two objects, one boundary:** the **host-internal `RunResult`** `{manifest, exit class, captured stdout/stderr (ceiling-marked), duration, kill-path taken}` never crosses to m-3 or any seat surface — captures are host-internal evidence under a bounded retention/discard policy. **What returns is exactly m-3's approved closed `CheckVerdict`** (`{check_id, claim_ref, outcome, rung_reached, predicate, timing, failing_detail}` — their §6 shape): no `output ref`, no path-bearing field; m-3's conductor-side redaction pass stands between the verdict and anything seat-deliverable (their §6.1, consumed not re-authored).
    - **The exactly-once claim, narrowed to what the machinery gives (F3):** the manifest's deterministic content-hash key guarantees **at-most-one COMMITTED verdict per manifest** — in-flight duplicate dispatches coalesce and completed outcomes replay through the A-2 intake machinery (one pivot, ever). It does NOT make the spawned process exactly-once: **a crash after spawn and before the verdict's atomic commit may re-execute the suite after recovery — at-least-once EXECUTION, by design**. The safety claim, scoped (r3/F2): re-execution introduces **no sanctioned/provided-surface side effect for a CONFORMING suite check** (read-only is the check contract + the provided surface, not OS enforcement); ambient same-uid misbehavior under repetition remains the explicitly accepted operator risk until the sandbox election — the conductor's actual guarantee stays one committed verdict / one pivot (the lean fit; a durable pre-spawn reservation protocol was rejected as machinery whose only beneficiary would be a side-effecting class v1 refuses). The loop consumes the verdict inside the §3 step-4 stage; it binds into the same atomic commit as the record it judges (CQ-5 unchanged).

## §3 The NF isolation fixture (the m-7-hosted proof)

FX-EXE-1 (the NF): a suite-class probe check runs INSIDE the executor and reports **two separately-labeled sections**: (i) **handle-surface absence** — enumerate env, args, open descriptors, staged tree; assert zero store/config/outbox/socket handles or path text, zero credentials/signing material, the env exactly the §2.3 allowlist; (ii) **the ambient residual** — a statement (not an assertion of absence) that same-uid OS access remains, labeled as the accepted D5-family residual. The fixture FAILS if section (i) finds a leak OR if section (ii)'s wording claims more than §1 allows (the executable-claims discipline applied to the fixture's own text). Companions (r2 wordings per F3/F4/F5):
- FX-EXE-2: timeout ⇒ the §2.7 state machine in order — group SIGKILL · direct-child reap · bounded `kill(-pgid,0)`→ESRCH verification · only-then cleanup; the negative leg: a bound-expiring survivor ⇒ typed machinery fault, workdir PRESERVED, no cleanup.
- FX-EXE-3: the F3-honest property — concurrent duplicate dispatch coalesces to ONE committed verdict (in-flight A-2 leg); a completed manifest re-dispatch replays the same outcome with no second commit; a crash-before-commit re-executes and still ends at exactly ONE committed verdict (at-least-once execution, at-most-one pivot — the record count is the assertion, not "run count 1").
- FX-EXE-4: output past ceiling ⇒ truncated AND marked.
- FX-EXE-5: no-verdict fault ⇒ the NF-S6 class-conditional disposition through the outer gate (authority `held`, non-authority `rejected`).
- FX-EXE-6: the boundary shape — the returned object is byte-shape-exactly m-3's closed `CheckVerdict` (no extra field, no `output ref`, no path text — the planted-leak leg plants a host path in `failing_detail` upstream and asserts m-3's redaction pass catches it, co-owned with m-3's §6.1 fixture); a `side_effecting` entry reaching `spawn()` ⇒ the typed host refusal.

## §4 Out-of-scope lines (named)

No `side_effecting` execution in v1 — the class EXISTS in m-3's approved taxonomy (default-denied, operator-allowlisted, theirs); this host refuses it (Q10). No shared build cache (F2 fold; a future one is a design change with content-addressing + manifest declaration). No pre-spawn reservation protocol (F3 fold; rejected while all accepted runs are read-only). No network sanction. No executor-resident policy: which checks run, their intents, timeouts-as-policy = `s8-design-m3-registry`. No new record kinds here (the verdict rides m-3's observe outputs; m-2/m-3 own the field homes).
