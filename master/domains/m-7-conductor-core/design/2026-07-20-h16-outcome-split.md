## §2 — The shape (the canonical enum; the fail-closed encoding is MECHANICAL, not advisory)

```go
State           string // json "state,omitempty"            — PRESENT (∈ {accepted, rejected, held}) IFF post_commit_state == complete; ABSENT otherwise
DecisionState   string // json "decision_state,omitempty"   — ∈ {accepted, rejected, held}; ALWAYS present on new emitters; fixed at commit, NEVER relabeled
PostCommitState string // json "post_commit_state,omitempty" — ∈ {complete, pending, failed, unknown}; ALWAYS present on new emitters
// RelayID/IntakeID/Reason/Detail/Credential/Endpoint unchanged
```

- **The mechanical fail-closed rule:** legacy `state` carries the decision ONLY when the truth is one-dimensional; on `pending|failed|unknown` it is ABSENT — a state-only decoder matches no enum member and takes its error path; `state` carries the decision or NOTHING, never a different value.
- **Emission semantics:** `complete` — no unresolved derived work; `pending` — an unresolved fault whose remaining cursor is entirely blind-replayable, retry in progress; `failed` — parked (ceiling, an immediate park rule, or the §4a `realized-undelivered` terminal); **`unknown`** — a durable `running_or_unknown` attempt marker exists for a NON-blind-replayable hook with no terminal transition (a hard crash or resolution-write failure around a possibly realized effect): completion cannot be proved, re-execution is forbidden, disposition is evidence-first (§4a) and otherwise the operator's.

- **The one-shot discipline lives IN the commit decision:** the serialized writer validates every derived-work transition (operator resolutions, advances, parks, reopens) against the LIVE fold at commit — valid ⇒ the record commits ACCEPTED; duplicate / conflicting / stale / nonexistent-target ⇒ the record commits **REJECTED with a fixed typed class per case** (`duplicate-resolution`, `conflicting-resolution`, `stale-resolution`, `unknown-target`) — the disposition IS canonical bytes; nothing is "fold-inert" by unrecorded convention.
- **The rebuild predicate is order-FREE:** the fold consumes ACCEPTED transitions only; by the single-serialized-writer + commit-time check, AT MOST ONE accepted resolution exists per instance — no first-wins, no ordering consulted; rejected records are the anomaly rows (canonical, visible).
  **Belt-and-suspenders fail-closed rule:** should rebuild ever find two accepted resolutions naming one instance (tampering/divergence — impossible via the writer), the instance folds CONFLICTED ⇒ `unknown`-class, operator disposition; shuffled-slice rebuilds are deterministic by construction (set predicates only).
- **Operator-ONLY, honestly enforced:** operator records arrive as ordinary governed submits from an operator-role seat (channel-stamped `FROM` + role — the existing identity machinery; NEVER `From: system`); the commit-time check validates authority + instance state together.
- The commit-time and rebuild predicates for all cases are pinned; the rejection classes ride the m-2 confirmation (they surface on the operator form path).

## §4c — Auth quarantine + the offline recovery ceremony

- **The EFFECTIVE-QUARANTINE predicate (canonical resolution ALONE never clears):** a seat is effectively quarantined while **(its chain is CONFLICTED/unresolved) OR (a resolved canonical tip exists that the binding row has NOT yet durably realized)** — on current bytes the loop commits, publishes tables via `completeTurn`/`AfterCommit`, and only LATER runs `AfterAccepted` (`loop.go:156-186`, `main.go:286-303, 603-621`), so a chain-status-only clear would reopen the old bound credential BEFORE `MintOrReplace` replaced it — exactly the ruled zombie window.
- **Enforcement locus + typed contract (the current bytes cannot express this — `seat.Manager.Resolve` returns `(SeatMeta, bool)`, `binding.go:121-130`, and the channel maps every false to `auth:invalid-credential`, `server.go:277-301`):** effective-quarantine membership is DERIVED STATE over (the canonical chain-status fold × the durable binding row), computed BEFORE channels open and republished by the serialized writer; `Resolve`'s contract widens to carry a typed refusal: **`auth:seat-quarantined` is returned ONLY when the presented credential MATCHES the seat's bound credential AND the seat is effectively quarantined; every non-matching credential remains `auth:invalid-credential`** — no caller learns any seat's existence or status without already holding that seat's real bound credential (the leak rule, m-1 scope e).
- **Clearing (ordered, not assumed atomic):** the quarantine-clear publication happens ONLY AFTER `MintOrReplace` has DURABLY replaced the credential + `realized_mint_ref` — one atomic swap of the published auth state by the serialized writer after the repair callback completes; auth attempts can never interleave between binding replacement and the clear. A repair ERROR keeps the seat quarantined and the anchor outcome reports honestly per §2 (`decision_state: accepted` × `post_commit_state: failed` — never "usable recovery"); a CRASH after the anchor commit and before durable replacement retains quarantine across restart, because the pre-serve recomputation finds a resolved tip the binding does not realize — clearing requires the pre-serve pass to PROVE realization. No direct binding mutation ever becomes truth. Pre-realization, the old credential draws `auth:seat-quarantined`; post-realization it draws `auth:invalid-credential` (superseded).
- **The recovery is TOTAL — three conflict shapes, each reachable:**
  (a) **conflicted non-operator seat** — any live operator channel submits the governed anchor/disposition;
  (b) **conflicted operator seat with ANOTHER live operator credential** — the other operator submits in-band;
  (c) **no usable in-band path** (the motivating case: the sole-operator conflict — quarantine bars the only credential; the admin `-mint` is genesis-only after any non-genesis record, `main.go:577-600, 677-693`) ⇒ the pinned recovery is the **OFFLINE LOCAL ADMINISTRATIVE CEREMONY**:
  a ONE-SHOT mode of the SAME binary, on the store host, whose **phase −1 is the ROOT LOCK (F99): it acquires `store.AcquireRoot` BEFORE any root/store/binding/recovery touch and holds it through exit — the lock IS the exclusion**, per the locked s6 acquire-before-touch law; mutual exclusion with a starting/running conductor is the lock itself (the conductor blocks/refuses at the same lock while the ceremony holds it, and vice versa); **the conductor-socket liveness probe is a POST-LOCK DIAGNOSTIC only** (operator UX for "stop the conductor first"), never the exclusion mechanism — a stale socket file blocks nothing and a live conductor is excluded by the lock, not the probe. *(The rev10–rev12 "`-mint` precedent — the same lock" citation is RETRACTED: the live `-mint` path probes and mints BEFORE `AcquireRoot` (`main.go:112-122`, `:577-600`) — an unlocked writer, NAMED as an explicit prerequisite/companion defect for master's backlog; the ceremony's lock helper is designed SHARED-SHAPED so `-mint` converges onto it if the operator wills both fixed in one IMPL lane.)* The ceremony then (ii) runs the serialized startup writer phase itself (recovery → validation) and commits the anchor/disposition as an ordinary canonical record carrying `admin_provenance`; (iii) runs the repair (`MintOrReplace`) to durable realization; (iv) returns the fresh credential SYNCHRONOUSLY in the ceremony's own direct reply and exits. Custody = OS permissions on the store directory; the ceremony is a host binary verb with NO socket and is structurally ABSENT from the seat `submit/project/read` surfaces.
- **The TOTAL STATE/ACTION MATRIX (record applicability rides the exact canonical branch, never an aggregate boolean; eligibility stays derived from canonical chain state × durable realization):**
  (1) **chain CONFLICTED/unresolved** (incl. deficient-unanchored and conflict-with-no-anchor) ⇒ validate + commit EXACTLY ONE anchor/disposition, then repair to realization;
  (2) **resolved + unrealized** (a unique tip exists — via zero/one-legacy unambiguity, a linked chain, or an existing accepted anchor — but the binding does not realize it) ⇒ **NO selector record**: repair the unique tip (`MintOrReplace` with THAT tip's ref — the first realization, not a rotation);
  (3) **resolved + realized** ⇒ no repair; by default NO action (typed refusal — nothing to recover); delivery retry ONLY under the ambiguous-delivery rule below.
  **An anchor attempted against an already-resolved chain — resolved WITHOUT an anchor or BY an existing one — commits REJECTED with the fixed typed class `anchor-target-resolved`** (the canonical anomaly row; the §4a double-anchor CONFLICTED rule remains the tampering backstop). No branch double-anchors; no branch rotates without canonical authorization.
- **The ambiguous-delivery rule (every retry = a distinct canonical generation):** `MintOrReplace` always creates a new random credential while persisting the caller-supplied ref (`binding.go:94-118`), so a replay replacement against an already-realized tip would put TWO successive credential values under ONE `realized_mint_ref` — a rotation with no canonical generation boundary, violating the locked m-1 ruling (`102208:25, 33-41`).   **The retry pivot's body is SYSTEM-DERIVED (delivery retry is never an authority edit):** the ceremony COPIES `seat`, `role`, and `is_operator` byte-exactly from the current canonical tip — the ordinary parser requires those members (`submit.go:391-421`), so they are populated by the ceremony code, NEVER by the form (the ceremony form carries the target seat + `retry_reason` ONLY); belt-and-braces, the commit-time validator REJECTS any rotation pivot carrying ceremony provenance whose authority bytes differ from its predecessor tip with the fixed typed class **`retry-authority-delta`** — even buggy ceremony code cannot silently promote/demote. `retry_reason` is a plain NON-authority body member (operator-supplied provenance context; no security semantics ride it).
  **The provenance carrier is EXACT and non-forgeable:** ceremony provenance = the THIRD system-stamped header **`admin_provenance`** (string version enum, v1 value set: ABSENT = ordinary ingress; `"ceremony"` = committed via the offline ceremony intake path) — stamped by the COMMITTING WRITER only when the commit originates from the ceremony path; the anchor record and the rotation pivot REUSE this one header (the record class distinguishes them).   **The retry is SCOPED by the undelivered/ceremony-provenance predicate (exact canonical carriers only):** the ceremony rotates ONLY when (i) the current tip is an ACCEPTED `seat_mint` with `admin_provenance == "ceremony"`, or (ii) the chain is resolved by an ACCEPTED `mint-chain-anchor` with `admin_provenance == "ceremony"` whose selected tip the binding realizes (the anchor-repair delivery: the selected legacy tip is not itself ceremony-authored, but the realization the ceremony delivered is), or (iii) the current realization's canonical delivery disposition is the s6 terminal `realized-undelivered` (callerless repair realized it with no caller to deliver to — the locked ruling already makes replacement admin-path-only, and THIS is that path); a seat whose current credential was in-band delivered is refused. Because `admin_provenance` cannot enter through ordinary ingress (rejected `system-owned`; rejected records create nothing per §4), an ordinary accepted `seat_mint` can NEVER satisfy this predicate.
  **Idempotency/replay:** an existing accepted anchor for the seat ⇒ skip to repair (never a second anchor); each delivery retry commits its own rotation pivot as above; exactly one canonical anchor and one realized credential result from any crash/replay interleaving.
- **Eligibility (role bits REMOVED; branch-scoped):** the ceremony acts iff the target seat is in matrix branch (1) or (2) — i.e., effectively quarantined — or branch (3)'s retry predicate holds (operator retry invocation + the provenance predicate); it writes ONLY the anchor/disposition class (branch 1) and the ceremony-provenance rotation pivot (branch 3 retry) — nothing else, ever. The rev9 "operator-role AND quarantined" precondition remains CONCEDED as undefined: `role`/`is_operator` are members of every canonical `seat_mint` pivot, so a conflicted chain carries DISAGREEING authority bits, the unresolved tip cannot be consulted before selection, and the binding row's `SeatMeta.IsOperator` is derived mutable state that accepted records outrank. The authority is the CUSTODY BASIS alone (local + the phase −1 root lock + exclusive stopped-store = operator; m-1 re-rules this basis per F99, scope f), NOT the target's role bits; after selection, the selected tip's OWN canonical bytes govern the seat's authority. "No other usable operator" is operational guidance for preferring paths (a)/(b), NOT a machine precondition. Eligibility is a pure function of canonical bytes × durable binding realization: the same canonical history yields the same eligibility whatever the binding row claims, and no authority-disagreement case is unrecoverable.
- **The exit is canonical, never a binding edit:** the operator (or ceremony) anchor/disposition record selects the tip ⇒ the ordinary repair machinery realizes it ⇒ the quarantine lifts per the clearing rule above. **The security carve-out, stated:** this is the ONE exception to serve-despite-pending (§9 entry 6) — credential-generation conflict blocks the affected seat's AUTH, not the conductor.
