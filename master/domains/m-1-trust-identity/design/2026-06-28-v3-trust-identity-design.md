## 1. Thesis (reframed to Step-1 confusion-resistant; see §0.c)

A single **trusted courier (the conductor)** is the **sole *governed* writer** of an append-only relay store and stamps every relay's sender identity (`FROM`) from the **connection the relay arrived on**, never from a lane-supplied field. This yields **confusion-resistant SEAT identity (D4):** a *confused* agent has no tool to write the trusted field, so through the governed interface there is nothing to forge. **D5 residual:** a malicious same-uid process under attach can write the store directly or spoof — out of Step-1 scope; **"by-construction" is the shelved-wrap milestone (D3)** (§0.c), not the Step-1 claim.

This is net-new. The audit proved all three surveyed harnesses ship *self-asserted* identity, identically structured — the trusted field and the sender-controlled field are the **same value**:
- **v2.8.8:** agent-authored `FROM:` text; the only check (`role_from_consistency_error`, relay-lint.py:555-575) compares the author's `ROLE` to the author's own `FROM` — a self-consistent forgery passes. Forged-FROM defense is explicitly "designed, deferred" (adapters/README.md:52-54).
- **jcode:** `CommMessage.from_session: String` in the wire body (wire.rs:377-390); the server trusts it and **discards** the connection→session binding it already holds (`ClientConnectionInfo`, debug.rs:46-60, taken as unused `_client_connections`, client_comm_message.rs:120); `assign_role` writes arbitrary roles (comm_control.rs:769) with a self-promotion path (comm_control.rs:703-730).
- **claude-code:** each agent writes the recipient's inbox with `from: getAgentName()` (SendMessageTool.ts:157-171), gated downstream only by `msg.from === 'team-lead'` (useInboxPoller.ts:162,557).

The external sweep confirms the *mechanism* is well-trodden (SO_PEERCRED/SCM_CREDENTIALS, mTLS, Kerberos channel-binding, **SPIFFE/SPIRE** "calling from a specific process *is* the proof of identity"; object-capability "unforgeable reference / no ambient authority"; single-writer WAL; CT/Merkle as a *separate* tamper-evidence layer). The **contribution is the application** to agent-seat identity, a domain the field has not settled (closest published cousin: "Right to History"/PunkGo, arXiv 2602.20214). Port the principles; claim the application, not the primitive.

## 2. The model — an SMTP-inspired conductor (idiom + security model)

Adopt SMTP's **architecture and security model** over a **typed envelope** (the canonical object is the typed envelope, per m-2; **not** literal RFC 5322/IMAP wire). The conductor is a mail system whose security posture is **"not an open relay"**: authenticated-submission-only, stamps the sender, no anonymous injection.

| SMTP role | v3 m-1 component | Property it buys |
|---|---|---|
| MSA (authenticated submission) | `submit()` | no anonymous injection; auth required |
| SMTP AUTH / SASL credential | the minted per-seat credential (§3) | per-seat authenticated session |
| envelope `MAIL FROM` set by the MSA | channel-stamped `FROM` (SPF-analog) | identity from the channel, not the body |
| `RCPT TO` | `TO`/`CC` (recipient_picker, §6) | sender-selected, courier-validated recipients |
| `Received:` trace (each MTA stamps) | courier-stamped `PARENT` / timestamps | confusion-resistant lineage (§6; D5 §0.c) |
| MDA → Maildir | conductor delivers into per-seat mailboxes | governed-write mailboxes (claude-code inbox+lock pattern; D5 §0.c) |
| IMAP/POP retrieval | `project()` | seat reads only its own mailbox |
| DKIM (substrate signs the record) | reserved `certification` (deferred) | crypto-hardening seam (§8) |
| DMARC alignment | one-FROM rule (no header `From:`) | anti-spoof with zero alignment machinery |

The historical SMTP weakness (spoofing via envelope/header `From` divergence) is closed by **one FROM**: identity lives only in the system-owned envelope; there is no lane-writable display-FROM (the DMARC two-FROM trap, §1 of the external sweep).

## 4. The three invariants — PROVED for Option A (the load-bearing section; VP hard requirement)

**Threat model:** a **malicious lane** (a compromised/adversarial seat process) that can reach the conductor directly. Goal: produce a relay attributed to a seat it does not own (forge `FROM`), or write the store directly.

Five **deployment invariants** the transport must realize (the concrete realization is the orchestrator-flagged "fork-2 infra call" — named §11):
- **DI-1 (dispositioned — c6-fix m-1-F3, ◆VP):** the *wrap-grade* form ("lane processes have no write access to the store path" via separate uid / store-dir ACL) is a **D3-shelved wrap invariant**, NOT a Step-1 realization. **Step-1 I1 rides the m-7 interface guardrail:** the store path is **absent from every seat's tool surface** — a *confused* seat has no tool/verb/path that reaches the store, so the only ingress is `submit()` (D4/confusion-resistant). D5 residual: a malicious same-uid process can still write the store directly — accepted Step-1 risk (§0.c). Step-1 I1 is **guardrail-borne, not a lane-excluding store ACL**.
- **DI-2:** each seat's connection + credential is **OS-isolated** — a sibling lane cannot read another seat's credential or connection endpoint.
- **DI-3:** credentials are **unguessable** (sufficient entropy).
- **DI-4:** `mint_seat` is **conductor-only** — no agent-facing self-binding.
- **DI-5 (observe-integrity — rev2):** the conductor can read the lane's relevant **ground-truth** (workspace / git / process state) **directly, from OUTSIDE the lane's trust boundary** — an **observer-selected control property** (the read vantage is chosen conductor-side, outside the lane, which the observed lane cannot reach). So an observed-value field is the conductor's *own* reading; a *confused* lane has **no tool** to substitute or intercept it (D4). **D5 residual:** a malicious same-uid process under attach could manipulate the ground-truth source (e.g. git state) or the read path — out of Step-1 scope. So m-3's observed evidence is **conductor-observed, not lane-supplied**, for a *confused* agent (**confusion-resistant, not by-construction** — §0.c).

### I1 — governed-write / store-isolation (confusion-resistant; D5 residual, §0.c)
**Claim:** the conductor is the only writer of the store (relay records, INDEX, mailboxes).
**Mechanism (Step-1, guardrail-borne — c6-fix m-1-F3):** the store path is **absent from every seat's tool surface** (the m-7 interface guardrail) — a *confused* seat has no tool/verb/path that reaches the store, so the only ingress is `submit()` (D4/confusion-resistant). **D3-shelved wrap clause (NOT the Step-1 mechanism):** the wrap realization — store on a conductor-owned path with no write permission for lane processes (separate uid / `0700` / no path handle) — is the D3 future backend that would make this structural; **D5 residual:** a malicious same-uid direct store write is an accepted Step-1 risk (§0.c).
**Proof (Step-1, guardrail-borne):** a *confused* lane has **no tool/verb/path** in its surface that reaches the store (the m-7 interface guardrail, DI-1 Step-1 form). The only ingress to the store is `submit()`, which stamps `FROM`. ∴ every record a confused lane can produce was written by the conductor (confusion-resistant, D4). **D5 residual:** a malicious same-uid direct store write is out of Step-1 scope (§0.c); the OS-ACL/separate-uid version that would close it is the D3-shelved wrap invariant. **QED for the D4 claim, conditional on the m-7 guardrail.**

### I2 — channel-isolation (the confusion-resistance core; D5 residual, §0.c)
**Claim:** `FROM := lookup(connection)` maps each `submit` to exactly one seat; no lane can cause a submit to be attributed to a seat it does not own.
**Mechanism:** `mint_seat` (conductor-only) creates a fresh per-seat connection + unguessable credential `C_seat`, records `seat ↔ {connection, C_seat}` in the conductor's private binding table, and delivers `C_seat` only to that seat's lane. `submit()` resolves the seat from the presented connection; an unbound connection → no seat → reject. `FROM`/`ROLE` are stamped from the binding; any payload `FROM`/`ROLE` is ignored.
**Proof — enumerate the attack surface, show each is closed:**
- (a) **Lie in the payload** (set body `FROM` = victim): ineffective — the conductor never reads `FROM` from the payload; it stamps from the binding. *Closed (confusion-resistant): a confused lane's payload lie is inert against the governed interface; D5 §0.c.*
- (b) **Present the victim's credential** `C_victim`: requires obtaining `C_victim`, delivered only to the victim's lane over an OS-isolated path (DI-2) and unguessable (DI-3). *Closed under DI-2 + DI-3.*
- (c) **Open a new connection and self-declare as the victim:** the conductor honors only connections it minted and bound via `mint_seat`, which is conductor-only (DI-4); an un-minted connection resolves to no seat → reject. *Closed.*
- (d) **Borrow/replay the victim's connection handle:** requires access to the victim lane's OS-isolated connection endpoint (DI-2). *Closed.*

**Conclusion:** under DI-2/DI-3/DI-4 and the reject-unbound rule, a *confused* lane reaching the conductor through the governed interface **has no tool** to produce a relay attributed to a seat it does not own — its only ingress is `submit()`, which stamps `FROM` from the binding. **∴ the Step-1 strength claim is "confusion-resistant" (D4).** **D5 residual (attach):** a *malicious, same-uid* code-executing process **can** bypass `submit` by writing the store directly, and can reach the `operator`-relay channel — these are **explicitly OUT OF Step-1 SCOPE** (accepted risk). The WRAP backend that would make the stamp structurally unforgeable is the shelved re-launch (**"by-construction" = D3**, §0.c); the honest-fallback below already anticipated this (I2 → confusion-resistant).

### I3 — observe-integrity (rev2; the m-3 read-vantage property)
**Claim:** an observed-value field (m-3: `ACTIONS_GIT_REF`, `FINAL_GIT_STATUS_SHORT`, `achieved_evidence`, the done-predicate result) is the conductor's own reading of lane ground-truth, not a lane assertion.
**Mechanism:** the conductor reads the lane's workspace/git/process state **from outside the lane** (DI-5, observer-selected) at the `submit` pre-send gate, and fills the observed field itself; a *confused* lane has no tool to supply or intercept the value (D4). **D5 residual:** malicious same-uid manipulation of the read source/path is out of Step-1 scope (§0.c).
**Why DI-2 is necessary but NOT sufficient here:** DI-2 establishes *credential confidentiality between siblings* — it stops a lane impersonating another seat — but it says nothing about **read-vantage**. A lane could hold a perfectly confidential credential and still lie about its own workspace if the conductor took the lane's word for it. Observe-integrity therefore needs **DI-5 (an out-of-lane read path)** as a *distinct* invariant, orthogonal to DI-2. Identity (I2) and evidence (I3) are separate guarantees resting on separate invariants (both **Step-1 confusion-resistant**; the by-construction versions are D3-shelved, §0.c).
**Honest-fallback (same discipline as §4 I2):** where a Step-1 realization **cannot** meet DI-5 (the conductor has no out-of-lane read path and must accept the lane's self-report), the degraded label for that evidence is **"self-reported evidence / confusion-resistant," NOT observe-by-construction.** DI-5 constrains the deferred fork-2 infra realization at PLAN exactly as DI-2 does.

**Residuals** (the c5 sweep corrects the earlier "sole residual = operator misconfig" — attach adds a larger, accepted one):
- **(1) Attach / D5 — load-bearing:** on the operator-locked attach deployment (same uid; lanes hold Bash/curl), a *malicious, code-executing* process is **not** stopped by these mechanisms — **direct store write, `operator`-FROM spoof, and config edit are accepted Step-1 residuals** (§0.c). The mechanisms are **confusion-resistant, not malicious-proof**; the structural (WRAP) version is the shelved D3 re-launch.
- **(2) Operator misconfiguration** at mint time (binding a lane to the wrong seat) — a one-time, operator-owned channel→seat wiring error, not a per-message surface.
- **Deployment-fallback labels stand:** if a Step-1 deployment **cannot** meet DI-2, identity degrades to **"operator-attested / confusion-resistant," NOT by-construction** (Option B); if it cannot meet DI-5, evidence degrades to **"self-reported / confusion-resistant"** (I3). The design names all of these explicitly rather than over-claiming.

## 5. API surface — `submit` / `project` / `read` / `mint_seat`

## 6. On-disk shape + the system-field contract (converged with m-2)
