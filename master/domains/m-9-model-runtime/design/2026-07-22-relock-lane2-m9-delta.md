On open, the worker verifies both against its `assign`/`turn_open` values; **any mismatch (or an absent/unreadable identity record) is fail-closed** — the log is not appended to, not repaired, and not silently re-created; the worker reports the condition through the §4 degraded path rather than writing into a file whose provenance it cannot establish.

### 1.3 Canonical encoding, the common envelope, and per-`kind` field presence (F4.2 closed)

The chain makes a gap or in-place mutation decidable, not merely a truncation.
- **`segment_id`** appears on **every** record, so a record misplaced into the wrong file is decidable (§1.7).
- Counters (`seq`, `turn_epoch`, `round_index`, `rotation_index`, `first_seq`, `last_seq`) ride the **canonical-decimal-uint64 STRING** grammar (lifecycle r21 §2.7). No counter is emitted as a JSON number.

### 1.4 `seq` grammar + THE ONE ordered record-validation algorithm (F4.3 closed)
`seq` is **per-segment**, `"0"` at `segment_open`, strictly `+1` per appended record. Recovery reads the segment's **raw physical lines in file order** and evaluates them top-down by this single ordered algorithm — first match wins, so no two rules can both apply to the same bytes. **Step 0 is a STATE guard evaluated on the RAW BYTES before any parse; steps 1–6 are the record branches.**

0. **TERMINAL-STATE GUARD — the seal admits nothing (R3-F1, order corrected per R4-F1).** *Evaluated first, on every physical line, whenever the last accepted record's `kind` is `segment_seal`.* Let `B` be the next physical byte sequence in the file (parseable or not, complete line or torn fragment):
   - if `B` is **immediately adjacent to and byte-identical with the accepted seal's own raw line** ⇒ **collapse** (the single benign re-append exception, identical in effect to step 2) and re-apply step 0 to the next byte sequence;
   - **otherwise — ANY other byte sequence whatsoever** ⇒ **FAIL-CLOSED FOR THE WHOLE RUN** (§1.8 row 11a). This explicitly and deliberately includes a **torn or unparseable** fragment, a **same-`seq` conflicting** line, a **gapped or regressed `seq`**, a **wrong `prev_digest`**, a **second `segment_seal`**, and a perfectly-formed continuing record. **No such input may reach steps 1, 3, 4 or 5**;
   - if there is **no further byte sequence** (EOF) ⇒ the segment ends normally at its seal.
1. **Self-consistency:** `record_digest` fails to verify, the line is unparseable, or `kind`/presence (§1.3) is violated ⇒ **prefix ends before R**.
2. **Benign adjacent re-append:** `seq(R) == seq(last accepted)` **AND R is byte-identical to the last accepted record** ⇒ **collapse** — R is skipped, the cursor does not advance, and **the chain check of step 5 is NOT applied to a collapsed duplicate** (this is the only legal duplicate).
3. **Conflicting duplicate:** `seq(R) == seq(last accepted)` and R differs ⇒ **prefix ends before R** (ambiguous stream).
4. **Regression or gap:** `seq(R) ≠ seq(last accepted) + 1` ⇒ **prefix ends before R**. *(A replayed multi-record suffix regresses `seq` and is therefore rejected here — fail-closed, never silently re-merged.)*
5. **Chain:** `prev_digest(R) ≠ record_digest(last accepted)` ⇒ **prefix ends before R**.
6. **Accept R.**

**Why the guard is FIRST, and why it is fail-closed rather than a truncation.** **No legal producer path writes into a segment after its seal** — the seal is the last thing the writer puts in that file before moving to the successor (§1.7). Post-seal bytes are therefore *positive evidence that a second writer touched a sealed segment*, which is exactly the property-(ii) violation the fence exists to make loud; silently truncating before them would report a clean prefix over a proven double-writer. **Ordering is load-bearing, and r4 got it wrong:** the algorithm is first-match-wins, so placing the terminal rule *last* meant only a well-formed, next-`seq`, correctly-chained record ever reached it — a **torn**, **conflicting**, **gapped** or **mis-chained** post-seal suffix matched an ordinary termination branch first and returned a *clean prefix ending at the seal*, contradicting the universal claim the rule makes. Four of the five post-seal shapes were therefore uncovered, and the one fixture I had exercised only the shape that happens to survive steps 1–5. The guard is now **state-dependent and evaluated on the raw bytes before any parse**, so the covered domain is exactly the domain the rule claims. It remains **strictly before §1.8(g) marker selection**, so a complete, perfectly-formed stale round appended after a seal can still never be selected as the trusted boundary.
**Seal uniqueness:** at most **one** `segment_seal` may be accepted per segment; a second one is a post-seal byte sequence and is caught by **step 0**.
**A conservative residual, named not masked:** a **torn** re-append of the seal is not byte-identical, so it fails closed rather than collapsing. That is deliberate — a torn post-seal fragment is indistinguishable from a stale writer's torn append, and under a rule whose whole purpose is to make a second writer loud, the honest disposition for an indistinguishable input is the fail-closed one. The cost is a rare false fault on a benign torn retry of the seal itself; the alternative would be a silent pass on a real double-write.
**Legal duplicate scope, stated exactly:** only an *immediately-adjacent, byte-identical* repeat of the last accepted record collapses. Every other duplicate — conflicting, non-adjacent, a replayed suffix, or one appearing after later `seq` values — terminates the prefix at that point.

### 1.5 `round_marker` — exact, mechanically provable round membership (F4.1 closed)
**The membership key is the ROUND KEY `{turn_id, round_index}`, never a bare `round_index`.** `round_index` is contiguous **per turn**, so a bare index collides across turns by construction — r2's predicate compared the index alone, which let a later turn's ordinary round `"0"` invalidate an earlier turn's round `"0"` and let a foreign-turn record sit inside an interval.

**Containment (normative producer obligation).** A round is **wholly contained in one segment**: rotation occurs **only between admitted rounds**, never mid-round. Because `seq` is per-segment (§1.4), this is what makes `[first_seq, last_seq]` + its marker a single well-formed interval; a marker whose interval would span a segment boundary is **not producible**, and on read a marker whose interval is not wholly within its own segment fails clause 1.

A `round_marker` carries the round key (`turn_id` in the envelope, `round_index` in the payload) plus `{first_seq, last_seq, marker_digest}`, where `marker_digest` = **SHA-256 over the JCS of the ordered array of `{seq, record_digest}` for every record in `[first_seq, last_seq]`**. It is **honoured only if ALL of**:
1. `[first_seq, last_seq]` lies wholly within the marker's own segment, and every `seq` in it is present and **accepted by §1.4**, with `record_digest` matching the digest input;
2. **every** record in the interval is **admit-eligible** (§1.3) **AND carries exactly the marker's ROUND KEY — both `turn_id` and `round_index`** (no cross-round *and* no cross-turn member);
3. **no admit-eligible accepted record OUTSIDE the interval carries that same round key** — the exclusion is quantified **over admit-eligible accepted records only**, and therefore **excludes the `round_marker` itself and every non-admit-eligible kind** (a `round_marker` is not admit-eligible, §1.3). *(r2's clause said "no record"; the marker — sitting at `last_seq + 1` carrying that same `round_index` — violated it, so the predicate defeated its own marker. Closed by the eligibility restriction plus the key.)*
4. the marker's `seq` is `last_seq + 1`, and the marker's `turn_id` equals the interval members' `turn_id`;
5. the recomputed `marker_digest` matches.
Otherwise the marker is **not honoured** and the prefix ends before it.

**What this makes decidable:** an omitted eligible member (clause 3), an extra or cross-round member (2), a **cross-turn** member or a same-index-different-turn collision (2 + 3 via the key), wrong order or a corrupt member (1 + 5), a non-eligible member (2), and an interval straddling a rotation (1). Consequently *"in the chained prefix"* and *"admitted to the valid prefix"* cannot disagree at the settlement proof.

**Duplicates never reach this predicate (alignment with §1.4 — the r2 fixture contradiction removed).** A physically repeated line is resolved by the §1.4 ordered algorithm **before** marker evaluation, so a marker is **never** "rejected for a duplicate member":
- an **immediately-adjacent byte-identical** repeat is **collapsed** and never enters the accepted run — it is **not a second logical member**, and the honoured interval is unaffected;
- every **non-collapsible** duplicate (conflicting, non-adjacent, replayed suffix, or one appearing after later `seq` values) **terminates the prefix before the marker**, so the marker is never evaluated at all.

### 1.6 THE WRITER FENCE — a single **PER-RUN** exclusive lock (F1 corrected; branch (a) retained)
**Correction accepted in full.** r1's fence was unsound on two counts, and I state both plainly: (1) it locked the **active segment file** while giving each generation its **own** segment — so predecessor and successor locked **different inodes and both could succeed**; the lock never excluded the cross-generation writer the property is about. (2) It asserted that m-10 always orders successor assignment after predecessor **reap**; the frozen bytes (m-10 r40 §B.2:68, re-read this session) say the lease passes when the prior generation is **"proven terminal (reaped) OR the operator disposes of it explicitly"** — I had consumed only the first disjunct, so on the **disposed-but-live** branch a predecessor can still be running. *(This is the third time I have asserted a sibling property without reading its full clause; the corrected fence below is deliberately built so that it does **not** depend on that upstream ordering at all.)*

**The fence (m-9-owned branch (a), correctly scoped):** a **single stable PER-RUN lock identity shared by every generation** — a dedicated lock file `<per-run runtime dir>/session.lock`, **not** any segment.
- **Primitive:** `flock(fd, LOCK_EX|LOCK_NB)` on that lock file. Chosen over POSIX `fcntl` record locks because `fcntl` locks are released when *any* descriptor for the file is closed in the process — a footgun for a long-held run lock; `flock` is bound to the open-file description and is released only when the last duplicate of that description closes (or the process dies).
- **Scope/lifetime:** acquired **before any recovery read that will be trusted and before any append**, and **held continuously across recovery + every append + every rotation + seal**, released only at process exit. Recovery-for-trust is inside the lock, so no generation can recover a prefix that another writer is concurrently extending.
- **Descriptor discipline:** the lock fd is opened **`O_CLOEXEC`** and is **never inherited by any tool subprocess** — the same no-inherit rule my frozen r21 §1.3 already applies to the CTRL-W/broker/DATA-P descriptors. Without this, an escaped `setsid` descendant (the ratified, still-open H-12 residual in r7 §3.3) could hold the run lock and deadlock every successor.
- **Fail-closed, including the disposed-but-live cut:** if the lock cannot be acquired, the worker **does not append, does not read-for-trust, does not force or break the lock, and does not create a parallel log**; it reports through §4 (`content_lost`/`DEGRADED`, or fail-closed run-terminal when even that path cannot be established). A disposed-but-unreaped predecessor therefore **blocks** the successor loudly instead of both writing.
- **Crash release:** process death releases the lock at the OS level — the successor acquires cleanly with no stale-lock reaping and no lease file to garbage-collect.

**Per-segment locks are demoted:** a generation may additionally lock its own active segment as a **local corruption guard**, but that lock is explicitly **NOT** cited as, and does not contribute to, the cross-generation exclusive-writer proof.

**Property (ii) now holds by:** *prevention* = the single per-run lock (one writer per run at a time, independent of the reap/dispose disjunction) + fail-closed acquisition; *decidability* = the §1.7 segment identity + successor-side chain with a frozen boundary digest, plus per-record `segment_id`/`generation_id`, so a stale or misplaced record is decidable from the durable bytes alone. **Neither leg relies on a bare `generation_id` label.**

**Residuals, named not masked:** `flock` is **advisory** — a writer that never takes the lock is not blocked by the OS. Under the ratified threat model (confusion, not malice) every writer is an m-9 worker that takes it, and the §1.7 chain makes any resulting stale bytes *decidable* even if they occur. `flock` semantics assume a **local filesystem**; a network filesystem for the per-run runtime dir is **out of scope for the MVP and would require re-deriving this fence** — named here so it is never silently assumed.

### 1.6a THE AT-REST DESCRIPTOR BATTERY — every content-bearing file opened symlink-safe and verified on the OPEN descriptor (M1-JOIN-F1)
**The gap m-1 caught, stated plainly: every §1.6/§1.7 check is a LOGICAL-RECORD check.** The per-run lock, the chain topology, `segment_id == filename`, and fsync durability all prove the bytes are internally consistent — **none establishes WHERE an opened descriptor points.** A pre-planted symlink, a rotation/handoff-race file swap, or a crash-restart substitution can redirect a content-bearing log into a workspace root or another file, and **every logical check above would still pass.** This is the exact R2-F1/F3 lesson m-1's own component was held to (*"a symlink/substitution path can redirect the durable content into a workspace or another file while all logical record checks still pass"*), and my r14 applied descriptor-grain safety to the §7 **C invocation** path while leaving my **own** D1 log and segment files — separate, worker-owned, on-disk artifacts carrying **open session content** (§1.1: *not* m-10-hosted, not m-10's private store) — with none. This closes it, symmetric with m-1 §2.3 + the m-7 §2.12 descriptor-safe pattern. **`flock`'s `O_CLOEXEC` (§1.6) covers the LOCK fd only; this is the LOG and SEGMENT fds.**

Normative, for the log file **and every segment file**, at every create/open/append/rotate:
- **Verified private parent dir:** the per-run runtime dir is `owner == euid`, mode `0700`; a parent that is a symlink, non-dir, wrong-owner, or group/other-accessible is **fail-closed** (no create, no open).
- **Exclusive symlink-safe CREATE:** `open(O_CREAT | O_EXCL | O_NOFOLLOW | O_CLOEXEC, 0600)`. `O_EXCL` defeats a pre-planted file; `O_NOFOLLOW` defeats a symlinked final component; a pre-existing path fails the create (segment ids are unique per run, §1.7, so a legitimate create never collides).
- **No-follow REOPEN** (recovery / append after restart): `open(O_NOFOLLOW | O_CLOEXEC)` — never a path that could traverse a substituted symlink.
- **Verify on the OPEN DESCRIPTOR (`fstat`, never `stat` on the path — TOCTOU-safe):** regular file (`S_ISREG`), `owner == euid`, mode `0600`, **link-count == 1** (no hard-link alias); record the `(dev, ino)` at first open and **re-verify identity across every append and rotation** — a changed `(dev, ino)` on the same logical file is a **replacement-race rejection**, fail-closed.
- **Containment on the OPENED OBJECT, never lexical path text:** any containment/location decision (e.g. that a segment lives under the per-run dir) is evaluated over the opened object + its resolved ancestry, **never** over the path string — the R2-F3 rule that a lexical check is defeated by a symlink even when the string looks contained.
- **Fail-closed disposition:** any failure — symlinked parent, swapped file, hard-link (`nlink > 1`), mode/owner drift, `(dev, ino)` change, `O_EXCL`/`O_NOFOLLOW` reject — takes the §4 fail-closed path (`content_lost`/`DEGRADED`, or run-terminal), **never** a silent open of the redirected target. **The at-rest fault report names the fault CLASS, never `session_log_path`** (the §1.12 m-1 carrier-negative extends here).
- **Conformance (RED-first, §10):** symlinked parent · swapped file between create and reopen · a hard link to the log/segment · mode drift `0600→0644` · owner drift · a replacement race changing `(dev, ino)` mid-append · a lexically-contained-but-symlink-redirected path — **each fails closed**, and a clean private-dir/regular-file/`nlink==1`/stable-`(dev,ino)` path proceeds.

**Residual, named:** this is confusion-resistance grain — the **same-UID malice** case (a process running as the same euid that races the descriptor within the OS's TOCTOU window) stays the explicit accepted residual, identical to the ceiling on m-1's own §2.3 and my `env_digest`/C-descriptor surfaces. The battery defeats symlink/substitution/hard-link/replacement **confusion**, not a co-euid adversary; H-12's external-use block is what covers the latter until Step-4.

**Branch-ownership (routed, not assumed) — unchanged in substance:** the fence and the segment scheme are keyed off the **existing frozen `assign.generation_id`** and a lock file I own, so on my reading this remains the **m-9-owned branch with no m-10 producer obligation**. If master or m-10 read it otherwise, that is a routing question to raise, not something to absorb silently.

### 1.7 Segments — canonical identity, the chain, active selection, and the rotation/handoff order (F2/F3 closed)
**Canonical segment identity (F3).** `segment_id` = the canonical string **`"<generation_id>.<rotation_index>"`**, where `rotation_index` is a canonical-decimal-uint64 string starting `"0"` for a generation's first segment and `+1` per size rotation **within** that generation. It is:
- carried in the `segment_open` payload **and** in every record's envelope (§1.3);
- **bound to the file on disk** — the filename is `seg-<generation_id>-<rotation_index>.log`, and recovery **verifies the filename components equal the `segment_open.segment_id`**; a mismatch is **fail-closed** (the bytes must prove which file they name);
- **unique per run** and **totally ordered** by `(generation_id, rotation_index)`.
This closes r1's gap where `segment_id` was load-bearing but absent from the schema and could not distinguish rotated siblings within one generation.

**THE ONE BOUNDARY EQUATION — non-self-referential, and identical for all three actors (R2-F2 closed).** Exactly one equation is defined, and the seal producer, the successor producer, and the recovery verifier all evaluate **this same equation over the same two named inputs**:

> **`boundary_digest(S) = SHA-256( JCS( {segment_id: S.segment_id, sealed_through_seq, last_record_digest} ) )`**
> where **`boundary_record(S)` = the LAST RECORD OF `S`'s OWN VALID PREFIX = the last honoured `round_marker` (§1.5) in `S`'s accepted run; if `S` has NO honoured marker, `boundary_record(S)` = `S`'s `segment_open` (`seq` `"0"`)** — and **`sealed_through_seq` = `boundary_record(S).seq`**, **`last_record_digest` = `boundary_record(S).record_digest`**. `boundary_record(S)` is **never** the `segment_seal`.

**ONE definition, both paths (R3-F1).** r3 stated the sealed and unsealed cases as two different rules ("the last record before the seal" / "the last record of the recovered valid prefix") and left the **zero-round** case — a segment carrying only `segment_open` — undefined. There is now exactly one definition, and it is **total**:
- **The `segment_open` fallback is the canonical zero-round encoding.** Every segment has a `segment_open` at `seq` `"0"`, so the boundary is always a **real record** — no sentinel is invented and no `sealed_through_seq` is fabricated. A crashed predecessor containing only `segment_open` (row 8 → handoff) freezes at `seq` `"0"`, which says exactly what is true: its valid prefix holds no content.
- **The two paths COINCIDE by construction**, because a seal may only follow an honoured marker (below). So "the last record before the seal" and "the last honoured marker" are the same record on the sealed path — one equation, no branch.
- **Non-self-referential:** the seal's own `record_digest` (which covers its `boundary_digest` payload) is **never an input**.
- **Recomputed, never trusted:** the verifier independently locates `boundary_record(S)` from `S`'s own accepted run (§1.4) + honoured markers (§1.5). A `segment_seal.sealed_through_seq` disagreeing with the recomputed `boundary_record(S).seq` is itself **fail-closed** — the seal's assertion is evidence, never authority.

**A seal may only follow an honoured `round_marker` (R3-F1).** The last accepted record before a `segment_seal` **must be an honoured `round_marker`**; anything else is **fail-closed**. This is the same containment rule §1.5 already imposes read from the other side — rotation happens only **between** admitted rounds, so a writer that is about to seal has just admitted one. It is what makes the frozen boundary and the *trusted* boundary the same record, and it removes the "unmarked content then seal" gap.

**What the boundary digest catches — and, honestly, what it does NOT (R3-F1).** r3's blanket claim that *any* post-link predecessor append changes the re-derived boundary was **false**, and I withdraw it:
- **Sealed predecessor + post-seal bytes** ⇒ caught by the **terminal-state guard** (§1.4 **step 0**, evaluated on the raw bytes before any parse), **not** by the digest — by construction the equation ignores everything after the boundary record. Fail-closed (row 11a).
- **Unsealed predecessor + a late write that MOVES its valid boundary** (an honoured marker appears past the frozen point, or a prefix record is mutated) ⇒ re-derived `boundary_digest` **≠** the successor's recorded `prior_boundary_digest` ⇒ **fail-closed** (row 11b). This is the cut that matters: a linked prefix can never silently move.
- **Unsealed predecessor + a late write that never reaches an honoured marker** (an unmarked or torn suffix) ⇒ the boundary is **unmoved**, so there is **no mismatch and no false alarm** — and no trust either: those bytes are outside the valid prefix and stay there (row 11c). Claiming a digest mismatch here would be dishonest; claiming trust would be worse.

**Forward-link equality, scoped to the edges where it is meaningful (R2-F2 as amended by R3-F2).** Where a `segment_seal` exists and the actual successor is of the **SAME generation**, recovery requires **all three**: (i) `predecessor.segment_seal.next_segment_id == successor.segment_open.segment_id` (forward); (ii) `successor.segment_open.prior_segment_id == predecessor.segment_id` (backward); (iii) `successor.prior_boundary_digest == predecessor.segment_seal.boundary_digest`. Any disagreement ⇒ **fail-closed**.
Where the actual successor is of a **DIFFERENT generation**, the seal's `next_segment_id` is an **unrealized same-generation intent** and is **NOT compared** — this is a reachable, ordinary state (a rotation seal committed, the successor file never appeared, and a *replacement generation* took over: row 6 followed by row 13), and failing it closed would reject a legal history. The load-bearing checks (ii) and (iii) bind in **both** cases, and `next_segment_id` must always be internally consistent (`"<own generation_id>.<rotation_index + 1>"`). A **terminal** seal carries no `next_segment_id`, so (i) does not arise.

**The COMPLETE chain topology predicate (R2-F2) — "one unsuperseded tail" alone was not a chain predicate.** Over the set **E** of enumerated segments with valid identity (filename ↔ `segment_id`, §1.7), recovery must establish **ALL** of:
1. **exactly one genesis** — precisely one segment in E with no `prior_segment_id`;
2. **no orphan / missing predecessor** — every non-genesis segment's `prior_segment_id` names a segment **present in E**;
3. **no fork** — no two segments in E share the same `prior_segment_id`;
4. **exactly one tail** — precisely one **unsuperseded** segment (S is superseded iff some S′ ∈ E has `prior_segment_id == S.segment_id`);
5. **acyclic and total** — the walk genesis → tail visits **exactly** E (equivalently: E is one connected acyclic path; a cycle, a disconnected component, or an unvisited segment all fail);
6. `segment_id` **uniqueness** across E;
