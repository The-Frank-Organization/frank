The worker fires the record and proceeds; the CONSUMED-no-record crash gap is **honestly parked `UNKNOWN_TOOL_OUTCOME`** — which is what makes async recording safe (not blocked-slow, not dropped-dishonest). The record rides the ordered CTRL-W channel in-order (protocol, not free telemetry). **This honesty is the anti-fabrication line** (§9 rail (a)): the worker never writes an outcome it did not observe.

## §6 — E0 population
*(the `m3.app_event.v1` rows the worker populates + carries, per m-3 r4; the worker is the E0 populator+carrier, m-8 emits none.)*
**6.1 The total disposition→E0 mapping (executable; realizes-against m-3 r4 `phase` tokens + m-8 r12 dispositions — the complete table is routed for m-3/m-8 confirmation, §11).** E0 emission is per-attempt and **non-guaranteed** (m-3 §1.4): a live worker emits; a **crashed** worker's populator is gone, so it emits NONE; emission is never a durability guarantee (m-10's durable `provider_attempts` row is the surviving truth on any absence — "liveness sets the E0 *value*, never guarantees its *emission*", lifecycle §2.6). There are two event kinds per attempt — one optional **non-terminal progress** event and, where a determinate terminal exists, exactly one **terminal** event:
- **`sent` (non-terminal progress) — bound to a frozen m-8-observable fact, NOT a wire-crossing claim (R3-F4).** Emitted ONCE per attempt, when the worker **observes m-8's `attempt_started{attempt_id}` normalized stream event** (m-8 r12:56) — which m-8 emits ONLY for attempts that passed its authorize (m-8 r12:71/84: `egress_denied`, `rejected_local`, and `cancelled(pre_transport)` produce **no `attempt_started`, no stream**). ## §7 — Session/context management + the GOVERNED compaction posture
*(GRILL-ratified: the governed 3-tier. "Compaction is a governed, auditable, evidence-preserving operation," not a token-saving heuristic — frank's evidence-first DNA applied to context. Grounded in an 8-harness production survey + an arxiv/industry sweep + two operator-provided field audits, §9.)*

**7.1 The state model (no second durable truth — lifecycle §2.6).** The worker holds **no durable m-9-owned canonical session store.** The `input[]` source is the **in-memory turn transcript**: a **derived, turn-scoped working artifact** that the worker accumulates across the attempts/tool-rounds of the *current* logical turn and re-assembles each attempt iteration. It is turn-cache content under the existing lifecycle §2.2 loop (the same custody class as the §2.8 replay-envelope) — it **dies at the turn terminal or park**, and **no durable row carries it**.
- **Canonical readable sources (the only truth — lifecycle §2.6):** (a) the worker's **own authored conductor records**, recoverable via `project{view: audit}` (`Envelope.From == seat`) + `read`; (a′) the **per-turn objective, located by `turn_open.admission_ref`** (m-10 r40 R37) — for `{kind: wake_relay, relay_id}` the durable task relay obtained through the worker's **own seat `read`** (the ref locates, never grants — I-PH intact); for `{kind: operator_input, task_input}` the verbatim task text carried ON the `turn_open` frame; (b) the worker's **own build artifact** (the static instructions/global constraints, `m9_worker_build_digest`-covered; build integrity validated by m-10's pre-admission serve/release gate F55/F63 — the worker does NOT resolve the opaque `manifest_digest` itself); (c) **fresh admission** — the worker starts each admitted turn under m-10's `turn_open`. m-10's `provider_attempts`/`tool_calls`/`turns`/ticket rows are m-10-private and frame-only; **the worker cannot and does not read them back** to reconstruct a transcript.
- **Derived-only representation + digest:** the in-memory transcript is a *derivation* over (a)+(b) + the current turn's live model/tool exchanges; it introduces no canonical fact. Where an integrity handle is needed (e.g. the Tier-0 survival check §7.3), the worker carries a **SHA-256/JCS digest over the derived pinned block** — a digest OF a derivation, never a second store of record.
- **Replacement/crash semantics:** on a worker crash or generation replacement mid-turn, m-10 parks the turn `INTERRUPTED` (lifecycle §2.9/m-10 §B.3) and the in-memory transcript is **gone — nothing durable to reload.** The replacement generation does **not** resume the transcript; it starts fresh under a new `turn_open`, rebuilding only its own authored conductor records via the audit projection (lifecycle §2.6). There is therefore no reload boundary at which a stale summary could be replayed or a nondeterministic provider summary re-run (§11.5 compaction note). **The objective, by contrast, IS stably recoverable** — the re-admission `turn_open` re-carries the byte-identical `admission_ref` (m-10 r40 R38-F1, post-commit emission), so the fresh Tier-0 block re-materializes to the same objective; this is the no-second-identity property that makes the §10 no-second-truth fixture provable.

Context within a live turn is managed as three tiers over that in-memory transcript:
- **Tier-0 PINNED** — the system prompt/instructions + global hard-constraints, the current objective, and per-task hard-constraints. **Authoritative every call (re-loaded/re-injected at §2.1), NEVER routed through the summarizer.** **Exact carriers + equality representation (owner-real; realized against m-10 r40 `turn_open.admission_ref`, R37):** the pinned block is re-materialized each call from two owner-real sources, NOT from the transcript: **(i)** the **static instructions + global constraints from the worker's own BUILD artifact** (baked at T4, covered by `m9_worker_build_digest`/F63; the `manifest_digest` in `assign` names WHICH build, but its **bytes/release binding are m-10-private — the worker does NOT resolve the digest; build integrity is enforced by m-10's pre-admission serve/release gate F55/F63**, which refuses to serve a worker whose artifact does not match the locked identity; frozen m-10 `run_manifest` §C.1 carries only policy/tool/lane/release identity, no instruction bytes); **(ii)** the **objective + per-task hard-constraints located by `turn_open.admission_ref`** (REQUIRED on every `turn_open`, never absent) — the closed two-kind union: **`{kind: wake_relay, relay_id}`** ⇒ the worker fetches the durable task relay through its **own seat `read`** (the legal surface; a `relay_id` is an id not a path, no authority transfers — I-PH intact), **`{kind: operator_input, task_input}`** ⇒ the operator's task text is carried **verbatim on the frame** (app-originated operator-authored content — not provider payload, not secret, the `app_event`-precedent CTRL-W content class). The objective is captured into turn state at turn start and re-injected from that captured copy. **Replacement recovery is provable by construction:** m-10 writes `admission_ref` into the `turns` row in the admission commit (the durable linearization) and emits `turn_open` post-commit from that row, so a crash/replacement **re-emits the byte-identical `admission_ref`** (no second task identity, no double wake-consume — m-10 r40 R38-F1) ⇒ the replacement re-materializes the SAME objective (re-`read` for `wake_relay`; the same verbatim `task_input` for `operator_input`). **The operator-input size ceiling is m-10-enforced (noted, not worker-visible):** an oversized `task_input` is refused at m-10's pre-commit `FRAME_MAX` gate with `admission_refused{reason: task_input_frame_overflow}` (m-10 r40 R40-F1) BEFORE any `turn_open` exists — so the worker never sees an oversized objective (nor the refusal); an accepted `task_input` is carried verbatim, never truncated. The survival check (§7.3) compares by **byte-identity of the canonical JCS-serialized pinned block** (a digest OF the re-materialized derivation) computed before vs after any rewrite. This is the Governance-Decay defense (§9): a compactor that drops a standing constraint pushed prohibited-action violations from 0% to 30–59%; pinning restores 0%. *(frank note: its **authorization** governance — F59/manifest/seat-identity — already lives outside the model context and is re-checked authoritatively every dispatch, so a compaction-induced confusion about authority **cannot** cause an unauthorized effect. Pinning here protects the **confusion layer** — the user constraints/objective the model acts on.)*
- **Tier-1 EVICT (primary, no LLM call)** — when over budget, **clear the bodies of the oldest tool results**, keeping the tool *call* + a `[cleared — re-read if needed]` placeholder and the last N tool pairs; the agent re-issues `read`/`bash` on demand. Coding context is dominated by tool outputs (file reads, greps, test logs) whose source of truth is on disk, so eviction is nearly lossless and **cheaper than summarizing**. *(= Anthropic context-editing `clear_tool_uses` / claude-code microcompact — `references/claude-code` `microCompact.ts` @ `6a25909`; the arxiv #1 pick, §9. The re-read-on-demand is itself a governed, F59-recorded tool call — eviction keeps auditability; it also *is* the "live-state re-injection" other harnesses bolt on separately.)*
- **Tier-2 SUMMARIZE (fallback, only if Tier-1 is insufficient)** — keep the newest N tokens verbatim + **one structured/typed-lite template** summary of the remaining *conversational* tail, then replace with `[summary, ...recent]`. The template carries explicit fields: **objective / hard-constraints / decisions+rationale / files-touched-with-paths / evidence-locators / next-step** (auditable and locator-preserving, ≈ prose cost; the pi `##`-schema shape, `compaction.ts:442-473` @ `94373d81`). The summary call **routes as a fresh ordinary m-8 attempt** (census correction, §11.5). Provider-native reasoning/tool blocks never cross the summary boundary (signature-safety; consistent with the turn-scoped `replay_envelope` custody).

**7.2 Triggering + the must-haves.** Predictive token estimate vs a budget of `context − max(max_output, buffer)` (buffer ≈ 20k), on the authoritative terminal `completed.usage` (m-8 §1.2:70). Two universally-required mechanisms (every surveyed harness has them): **(a) tool-call/tool-result boundary protection** — never cut between an assistant tool-call and its tool-result (else the next provider request is malformed); **(b) reactive overflow fallback** — on a provider context-overflow, **drop the oldest and retry** (terminal only if that still fails; refines the earlier "compaction-overflow is terminal" invariant).

**7.3 The integrity check (Governance-Decay defense).** After any Tier-1/Tier-2 rewrite, deterministically **assert the Tier-0 pinned constraints survived** the transform before the rewritten context becomes live. A deterministic gate — frank philosophy — at negligible cost.

**7.4 Explicitly NOT in the MVP (no opaque provider capsule).** frank does **not** use an opaque provider-native compaction capsule (e.g. OpenAI Responses' encrypted item): it is un-auditable (violates evidence/honest-labeling), it is provider lock-in (violates the model-agnostic DNA), and frank is `store:false`/stateless regardless. Compaction is an auditable transcript transform the worker owns. Deferred evolution rungs (noted, not built — §9): async validate-before-commit; a full typed capsule / indexed store with content-hash handles + rollback; learned controllers; semantic-boundary rubrics; anything training-gated.

## §8 — The two carried OWNER-BYTES pins (GRILL-ratified)
### §8.1 — L5: shared-client build-digest coverage — **B (separate artifact, referenced as a material)**
The shared conductor-client is its **own content-addressed build artifact with its own digest**; `release_digest` / the F58 build-identity vector pins the assembly; **`m9_worker_build_digest` references the shared-client digest as a MATERIAL (SLSA/Nix "materials list" style), not by inlining bytes.** Rationale (the software-development standard): package managers (lockfiles), content-addressed builds (Nix/Bazel), and supply-chain provenance (SLSA/in-toto) all treat a shared dependency as its own identified artifact and pin the assembly at a top-level lockfile/release that references components by digest; inlining a shared library into one consumer's flat hash is the non-standard shape. **End-app effect** (zero runtime difference): truthful change-attribution (the worker digest changes iff the worker's own code changes), single attestation of shared code, a narrow re-lock blast radius when the shared client is patched (the worker is not dragged through re-review), and clean layering (component attests itself, release attests the assembly).
