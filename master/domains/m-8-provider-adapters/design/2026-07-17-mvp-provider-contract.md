### 1.2 The normalized event stream (`m8.provider_event.v1`) — m-8 → m-9

Lifecycle grammar (the audit's promoted donor-convergent shape — grammar + block identity + typed terminal; NOT cumulative partials):

```
attempt_started{attempt_id}
  → ( text_start{block_id} → text_delta{block_id, text}* → text_end{block_id}
    | reasoning_start{block_id} → reasoning_delta{block_id, text}* → reasoning_end{block_id, replay_envelope?}
    | tool_call_start{block_id} → tool_call_delta{block_id}* → tool_call_end{block_id, tool_call{tool_call_id, name, arguments}}
    | usage{input_tokens, output_tokens, reasoning_tokens?, cache_read_tokens?} )*
  → EXACTLY ONE terminal:
      completed{finish_reason ∈ stop|length|tool_calls, usage}
```

### 1.4 Cancellation + chunk pacing

- **Cancellation intent arrives as a typed current-epoch signal, NOT as a raw closure (r9/R7-F2 producer half — reciprocating m-10 r27's provenance discipline).** A typed `cancel_attempt{attempt_id, turn_epoch}` on DATA-P (current-epoch) ⇒ m-8 aborts the HTTP context immediately, and the **ONLY carrier of a cancellation disposition is m-8's typed CTRL-C `attempt_result cancelled(<cancel_point>)` emitted on proven current-epoch cancel intent.** Two honest sub-cases, distinguished by whether transport was invoked (mapped in the §1.3 table, never `transport_failed`): (a) **pre-transport** (post-authorize, transport not yet invoked) ⇒ terminal `cancelled{partial:none}`, **zero wire send**, CTRL-C `cancelled(pre_transport)`; (b) **post-invocation** (stream was open) ⇒ terminal `cancelled{partial}`, CTRL-C `cancelled(post_invocation)` — the wire was crossed (no unsend exists; an in-flight request runs its course server-side; m-8 just stops reading and closes — never a claim of revocation, never a *failure*).
- **A bare DATA-P closure or an m-8/worker crash is channel-loss evidence, NOT a cancellation claim (r9 — the producer obligation m-10 r27 named):** m-8's raw-closure/abort path **cannot and does not emit a `cancelled` disposition** merely because the HTTP context aborted — no `attempt_result` is emitted on that path, and m-10 parks the row `UNKNOWN_PROVIDER_OUTCOME` (§B.3), never terminal `CANCELLED`. Cancellation is always a *typed, proven-intent* signal; loss is never silently upgraded to cancellation.
- **The CTRL-C `cancelled(<cancel_point>)` is a ONE-WAY notification (m-10 r27's total-ordered consumer):** m-8 expects **NO outbound response frame** to it (the inbound frame itself is the wire). A delayed/duplicate delivery is equivalence-keyed on the observable facts the frame presents — **`{attempt_id, reported turn_epoch, cancel_point}`** — and **the reported `turn_epoch` must equal the committed one to be equivalent** (post-epoch delayed delivery is idempotent BECAUSE its historical epoch matches, never because epoch is ignored); a duplicate **never downgrades a terminal `CANCELLED` row**. m-10's `cancellation_id` is **provenance-only** — m-8 does not carry it in the frame and never compares on it; correlation is m-10's durable relation, equivalence is over the three observable facts.
- **View reconciliation (m-10 r27 R23-F2):** `cancelled(pre_transport)` is an **m-8-view-only** close — zero wire, no stream, **no `attempt_stream_end` exists** for it; `cancelled(post_invocation)` is **two-view**, reconciled with m-9's `attempt_stream_end{disposition: stream_cancelled}`. Both rows exist once (the `attempt_open_ok` commit created them pre-DATA-P).
- Chunk pacing: m-8 emits events as they parse; one wire SSE event may fan into multiple DATA-P frames but never the reverse (no cross-event coalescing — block boundaries survive); every frame ≤ `FRAME_MAX` with oversized single wire events ⇒ `failed{frame_overflow}`.

### 2.2 The pipeline (order normative; each step's negative is a §8 fixture)

1. **Translate** — deterministic, versioned translation of `LLMRequest` × lane facts × compat profile → the exact wire body bytes. Pure function: same inputs ⇒ same bytes (property-tested). No credential, no auth header, no endpoint decision — the endpoint and method are copied from the lane catalog fact, never computed. **Lane-capability mismatch ⇒ typed reject, never silent transform (r1 — the m-9 C-3 pin; r4: its own reason token):** `reasoning.effort` present when the lane's `reasoning.supported=false`, or an effort value outside the lane's `effort_levels`, ⇒ the typed reject **`lane_capability_mismatch`** before freeze (its own `reject_reason` — distinct from schema-shape `malformed_request`; both close the attempt row terminal per §1.3) — translate() never drops or silently forwards a field the lane cannot honor (the fail-closed posture; m-9's side omits the field on non-reasoning lanes).
2. **Freeze** — build `frozen_core` + `frozen_core_digest`; the wire body bytes and the core are **immutable from this point** (held in m-8 as unexported/copy-on-read state; the mutability guard is the digest re-check at step 5).
3. **Authorize** — evaluate m-3 §1.3 (P0→…→P3 in the §1.3a total order, first failure = THE token) over the frozen core + the manifest facts (pinned lane, policy bytes verified against `policy_digest` at load — §5.3). 4. **Attach** — only now resolve S-A inside m-8, keyed by **exactly the envelope's `credential_ref`** (§3 — the run-frozen locator; possession of the file or the ref alone selects nothing: resolution occurs only here, inside the authorized operation, per m-1 1.4a), and construct the **wire object** = frozen core + exactly ONE added header: the envelope's `auth_profile.auth_header_name` with the resolved secret under `auth_scheme`. Attach + deterministic wire encoding are the ONLY post-freeze transforms (ratified §1). The auth header name is in `denied_header_names` (P0 membership invariant), so it cannot also exist in the frozen core — single-auth-bearing-transform, by construction.
5. **Send** — recompute `frozen_core_digest` over the about-to-encode core and require equality with the step-2 value (annex row 3, "authorized frozen-core cannot mutate"); verify the outgoing body bytes hash to `body_sha256`; **any inequality ⇒ send refused ⇒ the typed `rejected_local(internal_integrity_fault)` disposition per §1.3 (r6 — zero transport crossed; honestly not `transport_failed`, never `UNKNOWN`)**; then exactly ONE transport invocation via the §5.1 pinned no-replay transport, **counted at the connection boundary below the encoder** (r2/R1-F3 — an outer client call is not the proof; the wire attempt is). **Hash the frozen core, never the secret-bearing wire object** (ratified §1).

### 2.3 One attempt, no auto-retry — the suppression census (amendment §2a, realized)

One invocation ⇒ at most one transport attempt. **(r2/R1-F3 — the r1 claim that Go's transport replay "does not apply to POST bodies" was FALSE and is withdrawn:** the HTTP/1 transport retries a reused-connection failure when nothing was written and the body is rewindable via `GetBody` (`net/http/transport.go:815-849` at go1.26.4), and the HTTP/2 path has its own bounded retry loop with `GetBody` rewind (`h2_bundle.go:7893-7923,7965-7988`); a fresh context disables neither.**)** The no-replay property is therefore **structural, from the §5.1 pinned transport**: HTTP/1.1 only (h2 disabled — its retry loop cannot exist) · **no connection reuse** (`DisableKeepAlives=true`; every attempt dials fresh, and the HTTP/1 retry path fires ONLY on a reused connection) · **`GetBody` explicitly nil** (a bare non-rewindable reader; even a hypothetical retry path has nothing to rewind) — the two preconditions of every stdlib replay branch are both removed, and the §8 fixtures count **actual wire attempts at the instrumented connection boundary**, not outer calls. The remaining suppressed-surface census, each a §8 fault-injection fixture: no vendor SDK exists (owned client — the class is absent by construction) · no `Retry-After` handling (the header is recorded in `failed{provider_http}` detail, never acted on) · no SSE/stream reconnection (a cut stream ⇒ terminal `failed{transport}` or `cancelled`, plus `PARTIAL_STREAM` parking on m-10's side) · **no redirect following** (`http.Client.CheckRedirect` ⇒ error: a redirect is an endpoint change after authorize ⇒ `failed{protocol}`) · no automatic failover (one lane, one endpoint; no alternate exists) · no connection-retry middleware (none linked).
