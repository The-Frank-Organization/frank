## 1. Activation semantics — `layer_present:observe` (the §5 step-gate is unchanged; its INPUT becomes config-derived)

**Invariant (the headline rule): observe-layer activation is a governed, visible act — never a silent code default.**

- **The atom is unchanged.** `layer_present:observe` remains the §5 closed context atom (predicate.go implements `layer_present`; c1 §5 `:89`), and CQ-1 (`all_of(required_when, layer_present:observe)`) remains the step-gate for observe-owned fields. **No grammar change to the atom or CQ-1.** What changes is only where its *input* comes from.
- **The anti-pattern being removed:** today `PresentLayers` is a **hardcoded code constant** — `DefaultLayers()` (predicate.go:17) returns `{store:true, form:true, lineage:true}` (observe absent), consumed at `validate.go:29`, `render.go:54`, `render.go:259`. Flipping observe by editing that map would be a **silent code default** — exactly what the invariant forbids.
- **The rule:** the conductor composes `PresentLayers` **at load, from the governed config knob** — `{store, form, lineage}` always, **plus `observe` iff the config knob is set** — replacing the hardcoded `DefaultLayers()` absence. The knob lives in m-7's pinned config under the composite digest (CQ-4b), so activation is append-only, restart-relevant, and **visible in the digest** (§4 seam). A confused/ordinary lane has no tool to flip it (it is config, not a lane-writable field).
- **Executable fixture (named):** the **s5 dormancy sweep mirrors into an activation test** — the same Block-A fields asserted *dormant* when the knob is unset become *active at their per-class grain* (§3 matrix) when the knob is set: the seat-owned rows required+rendered, the conductor-observed/computed rows required-as-schema-declaration and satisfied by the conductor's observe stage (§3). One test file, two `PresentLayers` contexts (knob-off ⇒ observe absent; knob-on ⇒ observe present), asserting the CQ-1 flip **per ownership class** (not a uniform required/rendered). This is the invariant's proof: activation is only reachable through the governed knob, and the dormancy/activation pair pins both states.

**Recommended shape of the knob (m-7 owns the home; this is my grammar recommendation):** a single **boolean** "observe layer active" flag — the atom is binary (a layer is present or not), so the honest-minimal knob is one bool, not a per-writer or graded value.

**ONE immutable config-derived layer context, threaded through every predicate/digest site (rev1 — implementer blocker 2a).** `DefaultLayers()` is instantiated at **three** independent sites — `Render` (`render.go:54`), `Validate` (`validate.go:29`), and the grant-digest shape (`render.go:254-260`). Changing only the obvious render/validate calls would leave **split semantics** (e.g. a form rendered with observe-present but its grant-digest computed observe-absent). **Invariant:** the conductor derives **one immutable `PresentLayers` value from the pinned config at load** and threads that *same* context through **all** predicate-evaluation and digest sites — render, validate, and grant-digest alike. No site may fall back to the `DefaultLayers()` code constant once the config-derived context exists; the constant is retired to a genesis-bootstrap default only. m-7 owns the load mechanism (§4); my grammar requires the single-context threading.

## 2. Member grammar — the two new config members (the knob; the catalog), §9-compatible

Config is a **named-member map with a composite digest** (`config.go` `Pinned{Members, Engine, Registry, Digest}`; `Load(members map[string]string)`; `Digest(loaded)`). A member is a named, versioned artifact (the registry already carries a `version` field; the catalog carries `"version":"s7-v1"`). My grammar fixes the **§9 compat classification** so m-7's host has a grammar to bind both new members to.

### 2.1 The activation knob member
- **The MINOR classification needs a committed version carrier (rev1 — implementer blocker 3a).** rev0 called the knob a "config member" but §1 also allowed it as a **field inside `EngineConfig`** — which has **no version member** (`config.go:24-28`), and `json.Unmarshal` merely ignores unknown fields (`config.go:52-55`). "Additive-MINOR" is then a classification with **nowhere to encode or read it**. **Constraint on the m-7 home (§4):** the knob must land in a **version-bearing carrier** — *either* (a) a **dedicated versioned activation config member** (its own `version` field, like the registry/catalog), *or* (b) `EngineConfig` **gains an explicit `version` field** with exact bump semantics. m-2's grammar does not pick the home, but it **requires the home to carry a mechanically-readable version** so the MINOR class is detectable, not merely asserted.
- **Adding the knob member = additive ⇒ MINOR.** **Older-reader behavior = ignore-unknown ⇒ observe stays OFF — this is fail-CLOSED for activation** (a pre-s8 conductor composes `PresentLayers` without observe; it cannot accidentally activate). Safe. No migrator.
- **Flipping the knob value (off→on) is NOT a version bump.** It is a **governed config-digest change** (the composite digest moves; restart-relevant per CQ-4b) — the config-member *schema* is unchanged, only its value. This is the distinct-axis point I pinned at s5 CQ-4b: the **config digest** (activation/config integrity) is a separate axis from the **record `schema_version`** (record-schema evolution). Flipping the knob touches the former, never the latter.

### 2.2 The catalog member (`test/invariants/catalog.v1.json`)
The catalog is currently **`status: convention-only`** and carries the explicit s8 carry **`section_7_carry: s8-section-7-digest-pinning`** — s8 promotes it from convention to a **digest-pinned config member**. Its §9 grammar:
- **Promoting the catalog to a pinned member = additive ⇒ MINOR.** **But its old-reader behavior is fail-OPEN governance, NOT a safe default (rev1 — implementer blocker 3b).** An older reader that ignore-unknowns the catalog member **silently does not enforce the invariant laws** — a governance hole, categorically unlike the knob's fail-CLOSED observe-off. The honest statement: **legacy readers are weaker on catalog enforcement, and that is not safe.** **Rule:** if catalog enforcement is required for the governed s8 runtime, an old reader that cannot enforce it **must not participate** — but **NOT via a digest mismatch (rev2 — implementer blocker 2).** `config.Load` reads *every* supplied member into `loaded` and hashes *all* of it (`config.go:43-50,66-82`) while interpreting only `engine`/`fieldspec` (`:52-63`) — so a pre-s8 reader can receive the catalog bytes, compute the **same** composite digest, and still enforce nothing. **Digest equality proves bytes, not reader capability.** The mechanical stop must be a **reader capability/version gate** (m-7-owned): e.g. a **required config-format/engine version whose unsupported value fails load**, or a **required-member handler registry that rejects a pinned member lacking an enforcement handler**. m-2's grammar states the contract; m-7 owns the mechanism: **the composite digest binds bytes; a separate capability gate proves this reader actually enforces the catalog.** rev1's exclusion mechanism was false; this replaces it.
- **Adding a law = additive ⇒ MINOR.**
- **Removing / weakening a law = a governance-breaking change ⇒ gated by the catalog's own `change_convention` (`single_writer` + `owner_fidelity`)** — i.e., MAJOR-governance, owner-fidelity-reviewed, never silent. This *is* the INV-CATALOG's purpose (Cardinal-rule-1 tripwire); the grammar makes weakening a law loud, not a version-number nicety.
- **Version field:** the catalog keeps a `version` marker (`s7-v1` → advance on any law/shape change), mirroring the registry's version discipline, so a reader can detect catalog drift.

**One grammar, two members:** both the knob and the catalog instantiate the same rule — *add-member = additive-MINOR; value/law change is a governed config-digest act (config axis), not a record-schema bump; weakening is owner-fidelity-gated.* **Their old-reader defaults DIFFER (not a shared "safe default"):** the knob is **fail-CLOSED** (unknown ⇒ observe-off, safe); the catalog is **fail-OPEN** (unknown ⇒ no enforcement, unsafe — gated by the reader-capability check of §2.2, not digest equality). m-7's `s8-design-m7-config` binds its digest/pinning/capability mechanics to this grammar.

### 3.1 Stale-form precedence — the decisive re-render rule (rev1 — implementer blocker 2b)
rev0 claimed "re-render once, not a bounce-storm" without the mechanism. Today `Validate` records a stale `form_digest` re-render violation (`validate.go:22-24`) **and then continues** into required-set evaluation (`:27-65`) — so a pre-activation submission would receive **both** `form_digest:re-render` **and** newly-activated required violations for fields its stale form never showed (a confusing double-bounce). **Invariant (the decisive rule):** a **stale form digest short-circuits** — the submission gets **only** the typed `form_digest:re-render` disposition; required-set evaluation does **not** run against a stale form. After re-render, the seat resubmits on the **fresh** digest, which is then evaluated against the **activated** required-set. **Fixture:** stale (pre-activation) digest → exactly one `re-render` response → fresh form/digest → the activated required-set applies → accept-or-typed-required; **no retry loop, no double-bounce.** This makes "one governed re-render boundary" executable rather than asserted.

### 3.2 Forward-only migration — immutability held, NO re-validation (accepted direction, retained)
Records accepted *before* activation were **validly accepted** under CQ-1 (`layer_present:observe == false` ⇒ Block-A not required). Activation is **forward-only**: it never retroactively re-validates history. Confirmed against code (implementer-accepted): `store.Read` verifies the committed record (`store.go:161-175`), `Project` reads committed records (`:178-195`), and `migrate` applies only record-schema steps (`migrate.go:80-90`) — **none invokes the fieldspec required-set validation.** So a pre-activation record stays valid, is never re-validated against the post-activation required-set, and the store is not rewritten (§9 immutability). **Fixture (retained):** a pre-activation record `read`s/`project`s valid after the knob flips.
