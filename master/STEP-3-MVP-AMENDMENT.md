## §2a — The model/tool loop: turn vs attempt + MVP bounds (ext-review #6)
A coding agent runs a loop: provider attempt → tool calls → results → another provider attempt → … → final. Therefore:
- **"One attempt, no auto-retry" applies per provider INVOCATION** — never automatically retried (this covers **SDK retries, HTTP-library retries, connection-retry middleware, `Retry-After` handling, stream reconnection, automatic failover**). A **user-requested retry creates a NEW `attempt_id`** — never a silent resume/replay.
- **A logical TURN may contain MULTIPLE explicitly-recorded provider attempts** (the model/tool loop). "One attempt" ≠ "one turn."
- **MVP technical bounds (compiled constants — termination/resource safety, NOT a permission system):** max provider attempts per turn · max tool calls per turn · max wall-clock per turn · max streamed output · max captured tool output · cancellation behavior — fixed ceilings independent of the (Step-4) permission system.
