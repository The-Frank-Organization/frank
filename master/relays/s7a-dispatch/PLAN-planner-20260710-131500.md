### The defect (grounded @ `main@1d3e92c`)
`internal/fieldspec/predicate.go` `any_row` case: `array, rowField := strings.Cut(ref, ".")` then `validateGateReference(reg, owner, array)` — **only the array is validated**; `rowField` is dropped into the compiled `predicateAnyRow` unchecked. `routing_assignments` is `gate_referenceable: true` (`registry.json:173`), so `any_row:routing_assignments.chosen_model` — `chosen_model` being a model-identity **column** (listed in the routing_assignments prose column set) — compiles into a live predicate. The C1 column-grain trigger is met; R2 is violable at column grain today.

### Mechanism — RULED (mine per the dispatch): per-column validation at `any_row` resolution, backed by a MINIMAL per-column gate-referenceable allowlist (default-deny)
- **The check (logic):** extend the `any_row` parse path so that after `validateGateReference(array)`, it **also validates `rowField` against the row_array's per-column gate-referenceable allowlist**, rejecting with a typed error (`Field:Class`, I-PH) at registry load if the column is not allowlisted.
- **The metadata (data):** add a **minimal per-column gate-referenceable allowlist** to the `routing_assignments` FieldSpec (naming only the legal any_row column, `declared_deviated`). This is a **flagged registry.json data change** (bar v — see below). Every other column (incl. `chosen_model`) is **absent from the allowlist ⇒ default-deny ⇒ rejected**.
- **Why default-deny (allowlist), not a `model_identity` blocklist:** default-deny is the R2-faithful choice and matches §4 (`gate_referenceable` **default false**) + the c5 KEEP ("R2 structurally impossible to violate") — a **future** model-identity column added to routing_assignments is auto-rejected with no one having to remember to mark it. A `model_identity:true` per-column blocklist (the existing top-level convention on `model_name`) is default-**allow** and weaker for R2. *(Sketch (b) rejected on that ground.)*
- **Why NOT a full nested-column FieldSpec schema:** that is the **Step-3 carry** I fenced at s5-escalations (f) ("no grammar extension in s5; top-level carriers + prose columns + Step-3 column-grain enforcement"). This PLAN adds only the **gate-referenceable allowlist** the R2 guard needs — not per-column type/enum/required-when schemas. Minimal, in-fence.
