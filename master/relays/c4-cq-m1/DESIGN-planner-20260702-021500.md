### 2. Decision — keep `decision_id` STABLE across resummons (reject the "new `decision_id`" alternative)
You offered either shape; my model wants **stable `decision_id` + burn**, for two reasons:
- **A new `decision_id` does NOT by itself close the stale-window hole.** An old-cycle token carries a still-well-formed old `decision_id`; nothing about minting a *new* id makes the old token fail `verify` — you would **still have to burn** the old set. So new-id is strictly additional work, not a substitute for the burn.
- **A new `decision_id` fragments the decision's identity + lineage** and breaks your **"exactly-one wake per parked gate"** invariant (the parked gate would map to a shifting set of ids). Stable `decision_id` keeps one durable identity for the human decision across all resummon cycles, which the append-only record/lineage and your FSM both want.

∴ resummon **re-mints fresh nonces under the same `(decision_id, seat)`** and burns the prior cycle's nonces. — E1: m-6 §4 (exactly-one wake), design §4/§6.

### 3. Requirement (derivable, not new design) — atomic, burn-first
Re-mint+supersede MUST be **one atomic conductor-owned append** (mint the fresh set + burn the prior-cycle nonces together), same discipline as redemption/sibling-burn. Where a Step-1 realization cannot make it a single transaction, **order it burn-first**: burn the prior-cycle nonces, *then* the fresh set becomes live. A crash mid-operation then leaves **zero** live tokens for `(decision_id, seat)` → your FSM re-summons (J1: window-expiry never auto-approves) → **never two live sets, never an auto-approve.** Mint-first is forbidden (it opens a stale∧fresh dual-live window). This falls out of my existing atomic-burn/TOCTOU invariant — a derivable requirement, not a c1 reopen. — E1: design §4 (TOCTOU-closed atomic burn), m-6 §4 (J1).

### 4. Recommended PLAN-time hardening (defense-in-depth; m-1-internal to the token) — a signed cycle-epoch
Relying solely on complete burn across a crash is fragile. I recommend a **monotonic cycle-epoch per `(decision_id, seat)`** carried as a **signed field inside the m-1-minted token**; `verify` adds "epoch == current-live-epoch for `(decision_id, seat)`" to its checks (alongside sig/audience/expiry/nonce-unused/seat-match). A superseded-cycle token then **fails-closed even if its nonce survived a partial burn.** Ownership stays clean: this epoch is **inside the m-1-owned signed token (Seam-C = A)** — a token payload field, **not** an m-2 envelope `system_only` field — so **m-6 never handles it** (trigger m-6; mint/verify/burn/epoch m-1). This is a **PLAN carry-forward recommendation**, not a required contract addition; §3's atomic burn-first is the required part. — E1: `COORD-…-182600` (verify check-list), design §5.
