### (f) — degraded declaration shape for m-4's row_array / structured rows — **CONFIRM, with two mandatory Step-3 carry-conditions**

**The ask (from RECONCILE § m-2(f) + § m-4(f)):** the live fieldspec grammar cannot express **nested `row_array`
columns**; s5 proposes declaring m-4's structured rows as **top-level carriers + prose-documented columns**, with
**column-grain validation deferred to Step-3 (arrives with the router)** — no grammar extension in s5. Confirm
acceptable for the v3.0 routing record §3:164 expects.

**m-4 rows affected** (the structured ones; scalars declare fine):
- `routing_assignments` — `row_array`, per-row object `{ seat, role, task_tag, declared_bucket, chosen_model, declared_deviated, pin_mode, seat_archetype, authority_ceiling }` (§5:208). **The one that matters** — carries the model column + the `declared_deviated` gate-atom.
- `capability_prior_snapshot` — `type:object`, system/`computed_result` replay blob (§5:209). Opaque replay payload; top-level carrier + prose is natural.
- `constraints` — `type:object`, **reserved/forward**, no Step-1 values anyway (§5:212, §6:236).

**Why CONFIRM — this is faithful to the c2 lock, not a concession:**
1. **GL-3 (§51-56) already locked record-now / execute-Step-3.** v3.0 *records* the routing decision and rides
   existing runtimes; the conductor does not execute routing until Step-3. **There is no Step-1 routing writer.**
   Column-grain validation has nothing to validate in s5 (no lane/router writes a routing record yet), so deferring
   it to Step-3 — when the router that writes and reads columns arrives — lands the enforcement exactly where the
   consumer appears. The v3.0 job is to **declare the record shape** so the store can carry it; that is met by
   top-level carriers + prose columns + registered scalar fields.
2. **R2 is preserved by construction in s5, arguably strengthened.** A grammar that cannot reach into a carrier
   cannot make any nested column a gate predicate — so `chosen_model` physically cannot enter a `required_when`/
   `visible_when` while it is an opaque carrier. §5:217-218 ("model values appear only inside `routing_assignments`
   as payload — never in a predicate") holds trivially.

**Two mandatory carry-conditions on the Step-3 enforcement carry (these must NOT silently drop):**
- **C1 — R2 at column grain.** When column-grain validation lands in Step-3, `chosen_model` and any model-identity
  column MUST carry `gate_referenceable:false` / be non-predicate (m-2's flag). The by-construction R2 of the opaque
  carrier must be re-asserted explicitly the moment the grammar can address a column. This is the load-bearing
  invariant — it cannot be an afterthought of the router work.
- **C2 — the deviation-justification coupling.** `justified_deviation` + `deviation_reason_code` are top-level
  scalars (they register fine), but their `required_when any(routing_assignments.declared_deviated == true)`
  (§5:210-211) is an **`any_row` predicate** — inexpressible in the live grammar (RECONCILE: `any_row` is
  always-false at render). That coupling is the **readable half of the §2 (false,true) silent-deviation veto**;
  it rides the SAME Step-3 carry (arrives with the router that writes the rows). Deferring it is acceptable **only
  because no Step-1 lane writes a routing record** — nothing to gate yet. It must be enforceable the instant the
  router does.

**Net:** CONFIRM the degraded shape for s5, conditioned on C1+C2 being explicit line-items in the Step-3
enforcement carry (not vague "column validation later"). The declaration honesty GL-3 promises is preserved;
only its grammar-level *enforcement* moves to where its writer appears.
