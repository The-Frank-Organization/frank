## How each blocker is closed

**R2-F1 — marker membership (§1.5 rebuilt).** Four defects, all real:
- **The key.** `round_index` is contiguous **per turn** — I wrote that myself at §1.5 and then compared the bare index anyway. Membership is now the **ROUND KEY `{turn_id, round_index}`**: clause 2 requires every interval member to match **both** fields, so a foreign-turn record can no longer sit inside an interval, and clause 3's exclusion is evaluated on the key, so a later turn's ordinary round `"0"` no longer invalidates an earlier turn's round `"0"`.
- **The self-defeating quantifier.** Clause 3 now reads "**no admit-eligible accepted record** outside the interval carries that round key", quantified **over admit-eligible accepted records only** and therefore **explicitly excluding the `round_marker` itself and every non-admit-eligible kind** (a `round_marker` is not admit-eligible per the §1.3 table). The predicate can no longer be defeated by its own marker.
- **Cross-segment intervals.** I chose containment over a cross-segment interval identity: a normative producer obligation states a round is **wholly contained in one segment** — **rotation occurs only between admitted rounds, never mid-round**. Given per-segment `seq` (§1.4), that is what makes `[first_seq, last_seq]` a well-formed interval at all; a straddling marker is **not producible**, and on read fails clause 1.
- **The duplicate fixture contradiction.** Removed at the source rather than reworded: duplicates are resolved by the §1.4 ordered algorithm **before** marker evaluation, so **a marker is never "rejected for a duplicate member"**. An immediately-adjacent byte-identical repeat **collapses** and is *not a second logical member* (the interval is unaffected); every non-collapsible duplicate **terminates the prefix before the marker**, so the marker is never evaluated. The §10 fixture now asserts exactly that.

**R2-F2 — the seal/link/topology totality (§1.7 + §1.8 rebuilt).** Three defects, all real:
- **ONE non-self-referential boundary equation.** `boundary_digest(S) = SHA-256(JCS({segment_id, sealed_through_seq, last_record_digest}))`, where — normatively — those two inputs name the **LAST RECORD OF S THAT PRECEDES ITS `segment_seal`**, **explicitly not the seal record**. You identified the trap exactly: naming the seal would close a circle, because the seal's `record_digest` covers its own `boundary_digest`. The same equation is now applied by the **seal producer**, the **successor producer**, and the **recovery verifier** — one equation, three actors. I also added the leg that makes it non-forgeable in practice: **both inputs are RECOMPUTED by the verifier from the segment's own accepted run and are never trusted from the seal's assertion**; a `sealed_through_seq` disagreeing with the recomputed last pre-seal record is itself fail-closed.
- **Both-direction link equality.** On the sealed path recovery now requires **all three**: forward `predecessor.segment_seal.next_segment_id == successor.segment_open.segment_id`, backward `successor.prior_segment_id == predecessor.segment_id`, and `prior_boundary_digest == segment_seal.boundary_digest`. r2 checked only the backward pointer, so a contradictory forward link was acceptable.
- **The COMPLETE chain-topology predicate.** "Unique unsuperseded tail" was, as you said, not a chain predicate. Over the enumerated valid-identity set **E**, recovery must now establish **all** of: exactly one genesis · every non-genesis predecessor **present in E** · no fork · exactly one tail · **acyclic AND total** (the genesis→tail walk visits *exactly* E — a cycle, a disconnected component, or any unvisited segment fails) · `segment_id` uniqueness · **link-pair well-formedness** (`prior_segment_id` and `prior_boundary_digest` present together or not at all — otherwise clause 1's genesis test could be satisfied by an accident of an absent digest). **Any violation ⇒ NO prefix is claimed, fail-closed** — never a partial walk over the reachable part. §1.8's pass and crash **row 12** are rewritten to that predicate, and §1.11 (iii)/(iv) re-derived — which also caught a stale pointer of my own: (iv) still cited "crash row 7" from the 7-row table era; it now cites row 12 plus the filename↔`segment_id` binding.
