## The governing invariant (I design to it, not around it)
Verbatim VP: *"'label, never gate' cannot silently promote edited bytes as prior provider/tool truth across the frozen evidence-AND-current-presence invariant."* So the whole m-9 machine obeys: **a byte that differs from what was durably recorded is edited, and edited provider/tool content is re-classified OUT of trusted-as-original — never presented to the model as the provider's or tool's actual output.** That is the deepagents fabrication class (`patch_tool_calls` synthesising a cancelled tool result) my §9 faults; frank must not join it.

## 1. Detection (at which phase, by what)
Two phases, both on my content path:
- **At recovery/resume read:** each record's **advisory checksum** (`record_digest`, now advisory per Route-1 Ask-3) is recomputed; a mismatch on a **well-formed, complete** record ⇒ **edited-since-write** (distinct from a torn final record, which completeness catches and truncates). A record that no longer parses / violates §1.3 per-kind presence ⇒ **structurally edited ⇒ degraded** for that record.
- **At D2 consume:** a `settled_with_content` entry whose referenced content is present but **does not match its recorded content identity** (the round's `marker_digest`) ⇒ edited round.
Detection is thus **checksum-mismatch (content edit) + parse/schema-fail (structural edit) + marker-mismatch (round edit)** — all already computable on my path; no new frozen rule.

## 2. Labelling (surfaced how, to whom)
A per-record **`edited_since_write`** label (and, for structural, `edit_unparseable`), surfaced to: the **worker/assembly** (so it never treats the bytes as original truth), the **operator surface** (m-6/m-10 render — "this session was edited"), and the **evidence/E3** (m-3). The label is **carried, not inferred** — it rides the recovery result, not re-derived downstream.

## 3. Trust classification — TOTAL over content kinds (the heart)
| logged content kind | edited ⇒ trust class | why |
|---|---|---|
| `input_item` (user/assistant text) | **untrusted-but-model-visible, labelled edited** | model-visible context is legitimately editable (repair); it is presented, but as **edited**, never as an original transcript turn silently |
| `provider_output` | **untrusted-but-model-visible, NEVER "the provider's actual output"** | the fabrication guardrail: an edited provider record is model-visible only as edited content; it may **not** be presented or recorded as what the provider actually returned |
| `tool_result` | **untrusted-but-model-visible, NEVER "the tool's actual result"** | same guardrail — the deepagents class exactly |
| `compaction_event` / `objective_ref` / `workspace_snapshot` | **re-resolved / re-derived** where the reference is intact; **degraded** if the reference itself is edited unparseable | these are references, not provider bytes — an edited reference is honoured as a *new* reference and re-resolved against the run-immutable `admission_ref`, or degraded if unparseable |
| any record structurally unparseable | **degraded** (content_lost class) | cannot be trusted or presented as anything |
**Totality:** every content kind maps to `{untrusted-but-model-visible-edited, re-resolved, degraded}` — **no default-to-trusted**. An edited byte can reach **untrusted-but-model-visible** at most; it can never reach **trusted-as-original**.

## 4. Reconciliation with the settlement snapshot + receipt identity (SEAM — joint with m-10)
The m-9 side: an edited round's content no longer matches the receipt's round identity (`marker_digest`), and the referenced content differs from what was settled ⇒ on my path the round is **content-mismatch ⇒ re-classified edited-untrusted / `content_lost`→DEGRADED**, reconciled **after `turn_open`** (never trusted-settled). Crucially — **the m-10-canonical OUTCOME is UNCHANGED by the edit** (no-second-truth, r17 §5: content may persist, every outcome/decision stays m-10-canonical). So the edit re-classifies the **content** (model-visible) while the **recorded outcome** (what happened: the tool ran, the provider settled) stays m-10's canonical truth. **`receipt_conflict` STAYS FROZEN** — a historical edit emits **no second live `content_ready` frame**, so it never reaches m-10's live-ingress complement-of-equivalence gate; I do **not** prove it implicated (I decline the analogy to the blocked prescription). **m-10 owns:** whether/how its stored receipt identity + settlement snapshot record the content-vs-outcome divergence, and the re-anchoring of round identity across a sanctioned edit (couples to Route 5's `marker_digest`).

## 5. Disposition + first action
- **RESUMABLE-with-edited-labels** when the edited session is still assemblable (the repair case): resume proceeds; the edited content is assembled **honestly labelled untrusted-but-model-visible**; provider/tool records never presented as original.
- **DEGRADED / `content_lost`** when the edit renders a required round unparseable/inconsistent: the existing `content_lost`→DEGRADED path (r17 §3) fires; `resume_action = re_derive`; nothing edited is trusted or fabricated.
First action: assemble under the trust classification of §3; never a silent trusted-resume over edited provider/tool bytes.

## 6. Rebase-or-supersede (SEAM — joint with m-10)
- **Emergency hand-repair** (malformed-block class): treated as an **edit** per §1–5 — labelled, content re-classified, outcome untouched. No rebase of durable evidence.
- **Sanctioned edit** (a tool like `bivpak` deliberately rewriting): **supersedes the CONTENT** (the new bytes are the current model-visible content, labelled edited), **never the m-10-canonical OUTCOME**. What records the act: for the MVP, the **advisory-checksum-mismatch + the `edited_since_write` label** IS the record (no new durable "edit_event" needed for the MVP). **Full rebase-with-history = the Step-4 git-like session-versioning direction** (own implementation), where a sanctioned rebase re-anchors round identity across both stores; the MVP does **not** implement rebase — it labels. **m-10 owns** whether a sanctioned edit re-anchors its stored receipt identity or hard-conflicts (frozen behaviour); I flag that Route 5's `marker_digest`-as-round-identity must be **re-anchorable** by a sanctioned edit or the receipt hard-conflicts — a coupling for master to sequence.
