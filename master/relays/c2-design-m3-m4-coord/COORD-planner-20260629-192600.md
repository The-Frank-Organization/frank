### Q1 — derivation (m-4-owned): how `deviated` is constructed + what the snapshot comparison yields
- **Declared (gate-side, m-4):** per `routing_assignments` row, the planner fills a plain boolean `declared_deviated` (agent_enum_pick). The **only** model-touching predicate the m-2 schema gate ever sees is `justified_deviation.required_when: declared_deviated == true`. The atom is a plain boolean — **no `model_*` comparison enters the schema gate** (R2 by construction; locked R2 = `ARCHITECTURE.md:66-69`).
- **Observed (observe-side, conductor):** the conductor derives `deviated_observed` against the `capability_prior_snapshot` carried on the record. Construction: for the row's `(role, task_tag)` key, `deviated_observed := chosen_model ∉ prior_default_set(role, task_tag)`. v3.0 default: `prior_default_set` = the snapshot's **rank-1** model for the key (any non-rank-1 pick = a recorded deviation; the ranked tail informs the policy engine's *suggestions* but does not widen the no-justification-needed set). The exact width of `prior_default_set` (rank-1 vs top-k accepted) is an m-4 DESIGN-internal tunable; the seam only needs the comparison to be **conductor-derived from the snapshot**, never lane-supplied.
- **What the comparison yields** (per assignment): `{ prior_default_model, chosen_model, deviated_observed: bool }` — the observed atom you classify in Q2. Because the snapshot is system-filled and replay-complete, this derivation is reproducible at v3.1 benchmark time.
- **Net:** the model value lives in `routing_assignments` as payload; the schema gate reads only `declared_deviated`; the model-vs-snapshot comparison happens **only inside your observe layer**.

### Q4 — scope (m-3-owned; m-4 input as the writer of observability) — two tiers
- **Deviation-check observation (`deviated_observed`): on ALL routing decisions.** It is cheap (snapshot lookup + compare) and the silent-deviation veto only works if always run — observing "only deviations" is circular (the point is to catch *undeclared* ones).

So: deviation-check = always-on (the R2-preserving governance check); outcome-evidence = benchmark-sampled. This answers your Q4 three-way (all / benchmark-only / deviations-only) as **all for the cheap integrity check, sampled for the expensive outcome signal.**
