**The directive (three coherent parts):**

1. **Threat model = confusion & hallucination, NOT malicious adversarial agents.** We are reducing agents being *confidently wrong*, not defending against agents *trying to cheat* — even frontier labs with billions cannot solve the adversarial case, and we do not pretend to. The enemy is **inside and honest-but-wrong**. frank is a **confusion/hallucination firewall for fallible agents**, not a security product. This is not a pivot — it *enforces* the scope already on the record (c5 relabel `malicious`→`confusion-resistant`; the forgery-robust "wrap" **D3-shelved**; D5 residual accepted) against design ceremony that keeps re-importing the adversary we chose not to fight.

2. **Evidence mechanism = independent cheap-model adjudication + deterministic checks + honest labeling.** Objective claims (tests pass, code committed) → a deterministic check the courier runs trusted-side. The fuzzy majority ("refactored X", "found the root cause", "reviewed it") → a **cheap independent model reads the claim against the courier-captured real artifacts and judges consistency** — the judged agent cannot control the judge's output. It is **medium-strength, not proof**, and that is the correct bar: fabrication (or confident error) must survive an independent skeptic; cost moves free→real. Against confusion (not malice) the prompt-injection / doctored-input concerns largely evaporate — you need only feed the judge the *real* artifacts. **Prove it as a thin slice on a FRESH store** (sidesteps the adoption/migration machinery, which exists only to upgrade existing stores).

3. **Architecture = extensible seams, additive-not-closed, NO home-grown security.** Build the *slots* — the observe hook ("a place a verifier runs"), the evidence ladder (a graded structure), the identity stamp (a stamp slot) — and wait for vetted research to fill them; **never ship a security primitive we invented** (home-rolled adversarial defenses are the reliably-broken thing). Keep today's fills honest + minimal and labeled as what they are (channel-provenance = confusion-resistant, *not* tamper-proof). Mechanical rule for keeping a seam open: make it **additive/open** (a new evidence rung is ignored by old readers) not **closed/exhaustive** (a switch that rejects the new) — the same open-vs-closed distinction as the FieldSpec versioning grammar; structured identity that *could* later carry a signature, not a bare string that assumes it never will.

**Caution carried with the directive (prevents misuse):** this **REDUCES scope now — it does not add it.** "Support future security" is NOT a license to build speculative abstraction / a plugin framework on spec (doing-too-much in a new hat). The best extension point is a *clean minimal current design*. "Leave the door open" = don't weld it shut with closed assumptions; it is **not** "build the doorway for a door nobody's built."

**Positioning consequence (for the pitch/publication track):** lead with "**frank catches the confident hallucination the honor-system tools pass through silently**" (broad, honest — every AI-agent team has it), NOT "unfakeable / forgery-proof" (unbackable). Keep the identity-stamp's impersonation-catch as a **free byproduct to demo**, never a robustness claim to design or pitch for.
