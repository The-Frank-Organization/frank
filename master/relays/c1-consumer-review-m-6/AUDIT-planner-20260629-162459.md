**HUMAN_GATE_REQUIRED — owner:system, fill_constraints:monotonic — GAP G1 (m-2, local).**
The FieldSpec registry CAN express monotonic (m-2 §4 fill_constraints enum includes `monotonic`). But two
places make the field un-raisable as written: (a) §3's render table keys affordance on `owner`, and
`owner:system → "not shown (courier fills)"`; (b) §3's hybrid-picker clause that lets the agent select within a
system-supplied space names ONLY `parent_picker` and `recipient_picker` — it omits `monotonic`; (c) §12 tags
the field flat `owner:system`. Net: "the agent may only RAISE" (dispatch + §12) has no render affordance and the
owner tag would hide the control. **Fix (small, mirrors recipient_picker):** HUMAN_GATE_REQUIRED is a hybrid like
the pickers — system sets the floor, agent selects within `[floor, MAX]`, courier validates the pick is
monotonically ≥ floor; add `monotonic` to §3's hybrid-render clause; stop tagging it bare `owner:system`.
Sub-point: the floor is multi-writer (system baseline ∨ agent-raise ∨ m-5 archetype-ceiling-raise ∨ m-4 routing-raise) — monotonic must compose as the MAX across all raisers; a lower write never wins. Evidence: m-2 §3:34, §3 hybrid clause :39, §3 render table :41, §12 :175; FieldSpec :58.
